# Review and Reward Policy
## Contribution Network v1

### Principle

Rewards recognize useful protocol work.

They do not compensate:
- token purchase;
- trading volume;
- price support;
- holder count;
- speculative promotion.

### Review separation

Task default values are guidance.

Final approval records:
- approved Reputation points;
- approved pending MOOD amount;
- reviewer;
- reason;
- timestamp.

### Recommended review questions

Before approval:

1. Was the requested work actually completed?
2. Is evidence sufficient?
3. Does it satisfy task acceptance criteria?
4. Is the contribution original/non-duplicative?
5. Does it create value for Moodify Protocol?
6. Are any IP/data rights concerns unresolved?
7. Is reward within task-approved range/policy?

### Self-review

Production default:
- creator/submitter cannot review own contribution;
- admin identity and participant identity should be compared where possible.

### AI review

AI may:
- summarize evidence;
- run tests;
- check links;
- score against rubric;
- identify duplicates.

AI must not be the sole final authority for high-value rewards in v1.

Final approval remains an authorized human/admin action.

### Reward changes

If approved reward differs from task default:
- require reason;
- audit old/default and final value.

### Cancellation

A pending reward may only be cancelled with:
- authorized actor;
- reason;
- audit event.

Do not delete reward events.

### Reputation rollback

If a previously approved contribution is later invalidated:
- append a negative reputation event;
- do not rewrite/delete historical event.

This preserves auditability.
