# Moodify Power Reward Model v0.1

## 项目定义与实验执行规格书：响度匹配与清晰度约束下的音乐力量感成对偏好模型

**v0.1 - Prospective Project Specification**  
**荣景文川（深圳）科技有限公司 / Moodify Research Program**  
**日期：2026-07-24**

> 研究阶段：前瞻性项目规格，不含已完成模型效果。

## 执行摘要

Moodify Power Reward Model v0.1 是荣景文川从“声学处理软件”进入“情感模型公司”的第一个真实模型项目。它不直接生成最终母带，也不在 v0.1 阶段承担全自动处理，而是学习一个更基础、也更关键的问题：在响度基本一致、清晰度不被明显损害的条件下，人类更可能认为两个音乐版本中的哪一个更具有力量感。

该项目采用成对偏好学习。系统围绕同一个原始片段生成受控候选版本，经过响度匹配和清晰度门后，让听者进行 A/B 比较。模型不要求听者给出绝对分数，而是学习“版本 A 相对版本 B 更有力量”的概率。v0.1 的目标不是证明力量感存在唯一客观公式，而是验证：在明确的任务边界、上下文与约束下，人类偏好是否可以被稳定学习，并能否对未见过的曲目进行泛化。

项目的第一性原则是：先建立奖励模型，再训练处理策略。只有当 Moodify 能够可靠判断“什么结果更接近目标”，现有 DSP、Preset、参数搜索与未来生成模型才拥有可学习的方向。

## 1. 项目定义

1.1 一句话定义

在响度匹配与清晰度约束下，预测两个音乐候选版本中哪一个更具有感知力量感。

1.2 项目对象

输入由同一原始音乐片段 X 和两个处理候选 A、B 组成，并附带流派、段落、生成模型、播放环境等上下文 c。模型输出 P(A ≻ B | X, c)、不确定性和清晰度风险。

1.3 v0.1 不是什么

- 不是完整的自动母带模型；
- 不是从波形直接生成最终音频的端到端模型；
- 不是一个把“力量感”宣布为单一客观数值的理论；
- 不是以响度、低频或压缩强度作为力量感的替代指标；
- 不是正式宣称模型已经优于专业工程师。

1.4 v0.1 的战略意义

如果项目成功，Moodify 将第一次拥有一个由自身实验数据和人类偏好训练的专有模型。它将成为候选排序、参数搜索、主动实验和后续情绪模型的基础。

## 2. 科学问题与操作定义

2.1 核心问题

在候选版本响度匹配、技术质量达标且来源相同的条件下，哪些声学变化会使听者稳定地认为一个音乐版本更有力量？这种偏好能否被模型学习并泛化到未见过的曲目？

2.2 力量感的操作定义

v0.1 将“力量感”定义为：音乐片段在不依赖更高响度、不过度牺牲清晰度的前提下，呈现受控能量、冲击、重量、推进感和决定性的感知能力。

这个定义用于约束实验和标注语言，不作为预先写死的数学真理。模型最终学习的是人类成对偏好，而不是被要求拟合一个人工加权总分。

2.3 与相邻概念的区分

- 响度：声音整体能量感知，必须在比较前尽量匹配；
- 攻击性：可能包含刺耳、失真或压迫，不等同于力量；
- 重量感：力量感的一个组成部分，不代表整体；
- 清晰度：约束变量，不能因为增强力量而明显下降；
- 兴奋度：受速度、编曲与情绪影响，不能与力量感混为一谈。

2.4 可证伪假设

H1：在响度匹配后，听者对力量感仍能表现出高于随机的一致偏好。
H2：成对偏好模型能在按曲目隔离的测试集上显著超过简单声学特征基线。
H3：模型性能不能主要由残余响度差解释。
H4：加入清晰度约束后，模型推荐结果的可接受率高于只优化力量分数的版本。
H5：力量感偏好具有流派和段落条件性，不应被假设为无条件普适。

## 3. 形式化任务

给定原始片段 X、两个候选 Y_A 与 Y_B，以及上下文 c，奖励模型 r_φ 输出标量评分：

r_A = r_φ(X, Y_A, c),    r_B = r_φ(X, Y_B, c)

成对偏好概率采用 Bradley-Terry 形式：

P(A ≻ B | X,c) = σ(r_A - r_B)

其中 σ 为 Sigmoid 函数。训练目标是最小化人类偏好标签与模型预测之间的交叉熵。相近标签可编码为 (0.5, 0.5)；无法判断不直接进入主损失，但保留用于分析样本难度和任务边界。

未来处理策略的目标可表示为：

θ* = argmax_θ r_φ(X, T_θ(X), c)

约束条件包括：

|LUFS(T_θ(X)) - LUFS_ref| ≤ ε_L
G_clear(T_θ(X)) = 1
TP(T_θ(X)) ≤ TP_max

v0.1 只训练和验证 r_φ，不承担完整策略优化。

## 4. 数据生成协议

4.1 原始作品来源

v0.1 建议使用公司可合法研究和处理的 AI 生成音乐。每条数据必须记录生成模型、模型版本、提示词、生成日期、权利来源和允许用途。无法确认研究与训练权利的音频不得进入正式训练集。

4.2 最小数据规模

建议的 v0.1 数据规模：

- 60 首来源曲目；
- 3 个音乐家族：流行/人声、电子/节奏、电影化/器乐；
- 每首选取 2 个片段，共 120 个原始片段；
- 每个原始片段生成 4 个受控候选；
- 每个片段抽取 6 个高价值候选对，共约 720 个唯一对；
- 每对获得 3 个独立判断，共至少 2,160 条有效偏好记录。

该规模是工程起点，不是统计充分性的终局结论。若标注一致性不足，应先修改任务定义和候选设计，而不是盲目扩大数据量。

4.3 片段层级

每首曲目优先选择两个具有明确结构角色的片段，例如主歌/副歌、铺垫/高潮、主段/Drop。片段长度建议从 8-20 秒范围开始试点。最终长度由标注耗时、一致性和上下文需求共同决定。

4.4 受控干预轴

v0.1 只允许有限、可解释的处理轴：

- 瞬态与冲击：Attack、Transient emphasis、局部峰值塑形；
- 低频轮廓：低频重量、低中频支撑、低频动态稳定；
- 微动态与宏动态：局部对比、段落推进、压缩释放；
- 谐波密度：轻度饱和、主体厚度、纹理密度；
- 包络与处理顺序：相同模块在不同顺序下的结果。

每个候选必须由可复现的参数清单生成。禁止一次同时改变过多变量，以免失去解释能力。

4.5 负样本与边界样本

数据集必须保留：过度压缩、低频膨胀、瞬态刺耳、饱和失真、清晰度下降、响度匹配失败等候选。它们不能只被删除，而应成为失败标签和奖励投机测试集。

## 5. 响度匹配与清晰度约束

5.1 响度匹配

力量感比较必须尽量排除“更响所以更好”的简单偏差。v0.1 默认目标为候选间综合响度差不超过 0.1 LU；若渲染与测量条件难以稳定达到，可在试点阶段放宽至 0.2 LU，并在数据中记录真实差值。

所有候选应使用统一测量实现和版本。响度匹配只允许使用透明增益调整，不得因匹配过程额外改变动态、限制器行为或频谱。

5.2 峰值与削波

候选默认要求 True Peak 不高于 -1.0 dBTP，且不得出现数字削波。阈值为 v0.1 工程设定，应在目标发布平台和编码链路测试后再校准。

5.3 清晰度门

清晰度门由硬约束与软评价组成。

硬约束包括：无削波、无明显异常噪声、无声道错误、无渲染失败、无大幅度频谱塌陷。软约束包括：主体可辨识度、瞬态可读性、高频空气感、低频分离度和人声存在感。

初始自动代理指标只用于排除明显违规，不能被宣称等同于人类清晰度。人类标注中增加“清晰度是否明显下降”的辅助问题，用于训练或校准独立的 clarity head。

5.4 约束优先级

一个候选即使力量分高，只要清晰度违规，就不能作为最终推荐。未来多目标排序采用：先满足安全与清晰度，再在可行域中最大化力量偏好。

## 6. 人类偏好标注协议

6.1 标注任务

听者对同一原始片段的两个候选进行响度匹配后的比较，只回答：

- A 更有力量；
- B 更有力量；
- 二者相近；
- 无法判断。

辅助问题：获胜版本的清晰度是否明显更差？

6.2 标注语言

“力量感”指受控能量、冲击、重量、推进感和决定性，不要求更响、更刺耳或更压缩。听者应忽略可察觉的微小响度差，并在认为响度差影响判断时选择无法判断或标记响度异常。

6.3 听者结构

试点阶段至少包括两类听者：

- 训练听者：音频工程、音乐制作或长期听音经验者；
- 普通听者：目标用户，不要求掌握技术术语。

训练听者用于建立黄金测试集和边界判断，普通听者用于学习更广泛的感知偏好。两类数据应分别报告，不应无条件混合。

6.4 标注环境

记录设备类型、是否使用耳机、系统音量区间、环境噪声、自评熟悉流派程度。正式黄金测试要求使用经过基本校准的耳机或监听设备，并在安静环境中完成。

6.5 质量控制

- 每位听者先完成训练样本；
- 插入重复对，检验自洽性；
- 随机交换 A/B 顺序；
- 插入明显响度违规对，识别不认真标注；
- 允许相近与无法判断，避免强迫虚假选择；
- 记录响应时间，异常快速判断进入复核；
- 计算听者内一致性与听者间一致性。

6.6 在线反馈原则

偏好模型不能只依赖一次性静态标注。随着模型开始推荐新的候选，它会进入原始数据未覆盖的区域，因此应持续抽取高不确定、高分歧和高风险样本请人复核。

## 7. 数据结构与拆分

7.1 Power Pair Record

每个候选对必须记录来源、干预、约束、偏好、上下文和治理信息。最低字段见随包附带的 JSON Schema 与 CSV 模板。

7.2 拆分原则

训练、验证、测试必须按来源曲目隔离，而不是随机拆分候选对。来自同一曲目的不同片段、不同候选不得跨越数据集，否则模型可能记忆曲目特征而非学习力量偏好。

建议拆分：

- 训练集 70%；
- 验证集 15%；
- 冻结测试集 15%。

另外建立跨生成器测试集、跨流派测试集和专家黄金测试集。

7.3 防止数据泄漏

特征标准化、响度统计、候选选择阈值和主动学习策略都必须只在训练与验证数据上确定。冻结测试集只在里程碑验收时开启。

7.4 版本治理

每条记录绑定：音频哈希、处理链版本、模型版本、测量工具版本、标注协议版本和数据集版本。无法复现的记录不得进入正式训练集。

## 8. 模型路线

8.1 基线模型

B0 随机基线：准确率 50%。
B1 规则基线：使用响度、Crest Factor、低频能量、瞬态强度等特征训练逻辑回归。
B2 冻结音频嵌入基线：使用预训练音频编码器提取 X、A、B 表征，训练小型成对偏好头。
B3 Moodify v0.1：共享编码器 + 差分特征 + 上下文条件 + 清晰度多任务头。

8.2 推荐架构

v0.1 优先采用资源可控的 Siamese 结构：原始片段与两个候选通过共享音频编码器；模型计算候选相对原始片段的表征变化，再与上下文向量结合，输出两个奖励分数和清晰度风险。

编码器可以先冻结，只训练轻量头部。若数据规模和泛化结果证明必要，再逐步解冻高层。这样可以降低过拟合与算力需求。

8.3 训练目标

主损失：成对偏好交叉熵。
辅助损失：清晰度下降预测、响度差去偏、听者组条件校准。

总损失示意：

L = L_pref + λ_c L_clarity + λ_l L_loudness_debias + λ_r L_regularization

8.4 不确定性

使用 3-5 个不同随机种子或 Bootstrap 训练的奖励模型集成，输出平均偏好概率与成员分歧。高分歧样本优先进入人工复核。

8.5 主动学习

查询优先级综合：模型不确定性、模型间分歧、样本新颖度、潜在艺术风险和流派覆盖缺口。主动学习策略本身必须做消融，不能假设一定优于随机抽样。

## 9. 评价体系与验收标准

9.1 主指标

- 按曲目隔离测试集上的 pairwise accuracy；
- ROC-AUC；
- Log loss；
- Brier score 与校准误差；
- 与专家黄金判断的一致率；
- 各流派、段落、生成器和听者组的分组表现。

9.2 去响度作弊测试

- 将残余 LUFS 差单独作为基线特征；
- 对 LUFS 差做置换与消融；
- 构造更响但主观更弱的对抗候选；
- 检查模型分数与残余响度差的相关性。

9.3 清晰度测试

对模型 Top-1 推荐进行独立清晰度盲评，并计算清晰度违规率。力量模型不得通过模糊、刺耳、失真或过度压缩获得高分。

9.4 建议验收门

G0 数据可复现：≥95% 记录可由参数与版本重建。
G1 偏好可学习：测试准确率 ≥0.65，且显著高于随机和响度基线。
G2 跨曲目泛化：所有主要流派子集准确率 ≥0.60。
G3 去响度作弊：加入 LUFS 差后模型主要结论不消失，残余响度相关性受到控制。
G4 清晰度约束：Top 推荐清晰度明显下降率 <5%。
G5 闭环安全：对抗搜索中不出现高比例明显奖励投机结果。

这些阈值是 v0.1 的项目门，不是学术界通用标准。若未通过，应定位失败原因，而不是修改报告口径。

## 10. 八周执行计划

第 1 周：冻结项目定义、力量感说明、响度匹配与清晰度门；建立实验编号。

第 2 周：实现候选生成器、批量渲染、响度匹配、测量与哈希记录。

第 3 周：完成 20-24 首曲目的标注试点；检验片段长度、任务语言和一致性。

第 4-5 周：扩张到 v0.1 最小数据规模；完成重复标注和黄金测试集。

第 6 周：训练 B0-B2 基线；检查数据泄漏、响度作弊和流派偏差。

第 7 周：训练 Moodify v0.1 奖励模型；开展不确定性与主动学习试验。

第 8 周：冻结模型，执行跨曲目、清晰度与奖励投机测试；形成 Go/Revise/Stop 报告。

项目允许在第 3 周结束后暂停。如果人类对“力量感”在当前任务设计下无法形成足够一致的偏好，应优先修改概念边界、片段长度或候选设计。

## 12. 风险与防护

风险 1：力量感定义过宽。防护：先限定到特定流派和段落，允许相近与无法判断。

风险 2：模型学习响度差。防护：严格匹配、残差记录、对抗样本和响度消融。

风险 3：力量提升以清晰度损失为代价。防护：硬门 + 辅助标注 + 独立 clarity head。

风险 4：同曲泄漏导致虚假高分。防护：按曲目隔离拆分和哈希审计。

风险 5：听者群体差异过大。防护：记录听者条件，分组建模，不强求单一审美。

风险 6：奖励投机。防护：在线反馈、对抗候选、失败样本、人工复核。

风险 7：只保存成功候选。防护：保留所有候选、淘汰原因和曝光机制。

风险 8：版权和数据授权不足。防护：建立来源许可字段，未经授权的数据不得训练。

风险 9：指标漂亮但产品无价值。防护：最终增加真实工作室或介鹿音乐场景中的盲测。

## 13. 项目交付物

v0.1 完成后必须产生以下可审计资产：

1. Power Pair Dataset v0.1；
2. 候选生成与响度匹配流水线；
3. A/B 偏好标注界面；
4. 数据 Schema、实验编号和数据卡；
5. B0-B3 基线与模型权重；
6. 冻结测试集和专家黄金集；
7. 清晰度违规与奖励投机测试集；
8. 模型卡、限制说明和可复现实验报告；
9. Go/Revise/Stop 决策报告；
10. 后续 v0.2 参数搜索闭环任务书。

其中，数据协议、失败样本和评测集与模型权重同等重要。

## 14. Go / Revise / Stop 决策

GO：偏好具有可学习性，模型跨曲目超过基线，且不依赖响度作弊；进入 v0.2，用奖励模型指导有限参数搜索。

REVISE：标注一致性或泛化不足，但问题可定位到流派、片段长度、候选设计或听者分组；修改协议后重做局部实验。

STOP：在多轮严格控制后，人类对该操作定义仍无法形成稳定偏好，或模型只能依赖响度/清晰度损失获得高分；停止将“力量感”作为第一奖励模型，转向更可辨识的属性。

停止并不等于项目失败。它说明当前猜想没有得到支持，符合 Moodify 的实验漏斗制度。

## 15. 后续路线

v0.2：奖励模型指导 Preset 与参数搜索，但仍由人类复核高不确定候选。

v0.3：加入多目标约束，联合优化力量、清晰度、疲劳风险和艺术意图保持。

v0.4：扩展温暖感、亲密感、脆弱感等独立奖励模型，研究属性之间的耦合。

v0.5：引入人格条件，使同一 IP 在不同作品中保持稳定的力量表达方式。

长期目标：形成 Moodify Affective Reward Stack，以人类偏好、受控干预和因果证据共同指导 AI 作品的持续进化。

## 参考方法与研究状态

本项目的方法入口来自 Christiano 等人的“Deep Reinforcement Learning from Human Preferences”：当目标难以写成明确奖励函数时，可让人比较两个行为片段，训练奖励预测器，再用预测奖励指导优化。Moodify v0.1 只采用其中的成对偏好与奖励学习思想，不直接复现论文中的 Atari、机器人环境或强化学习算法。

本文档是一份前瞻性工程规格书。当前没有模型训练结果，没有宣称力量感可被单一分数完整表示，也没有宣称项目已达到商业部署条件。所有阈值、数据规模和架构选择均为 v0.1 的待验证工程假设。
