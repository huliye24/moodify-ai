# Moodify One Point｜原理种子

## 一句话

> **让这首音乐成为它自己。**

## 一个动作

> **成全。**

## 五条不可违背的工艺法则

1. **身份先于改善。** 先确认作品不可失去什么，再讨论能够改变什么。
2. **克制先于展示。** 技术只有在帮助判断时才应出现；存在不等于必须可见。
3. **可逆先于效率。** 不覆盖源，不抹去失败，不以方便换取不可恢复。
4. **诚实先于漂亮。** 知道、推断、不知道和需要人判断必须清楚分开。
5. **成全而不占有。** Moodify 提供候选、证据和边界，但不夺取作品与人的最终决定。

## 默认产品形式

操作者首先看到的不是模块、参数、指标或分数，而是：

```text
这首作品是什么？
什么必须留下？
什么可以被轻轻改变？
系统实际做了什么？
什么仍然需要人来决定？
```

## “空”的工程含义

空不是没有能力，而是不让能力争夺注意力：

- WSE/MSE/PPE 仍在，但不成为默认语言；
- 完整证据仍在，但不成为第一屏负担；
- 人工判断仍在，并被放在合法、清晰的位置；
- 未知仍在，并被诚实保留为空，而不是被算法填满；
- 系统做了大量工作，最后只留下必要的关系。

## 反面清单

下列结果不属于本次跃迁：

- 把“让音乐成为自己”写成 slogan，但产品结构不变；
- 新增一个漂亮页面，却继续堆叠全部指标和内部术语；
- 把复杂性藏到无法审计；
- 用一个总分代表作品身份；
- 自动宣称 improved、release-ready 或 Final；
- 为追求简洁删除失败、版本、证据或人工审批；
- 以大规模重写制造“焕然一新”的表象。

高级秩序的标准不是少，而是每个留下的东西都不可再删，每个隐藏的东西都仍可被找到，每个决定都知道自己属于谁。
