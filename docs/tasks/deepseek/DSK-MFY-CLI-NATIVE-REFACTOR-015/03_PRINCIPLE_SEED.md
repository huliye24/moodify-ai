# Principle Seed｜Moodify 本体就是 CLI

1. Moodify 的主要用户既包括人，也包括 AI Agent；稳定命令、schema、状态和证据比窗口布局更重要。
2. CLI 是产品合同，application API 是执行内核；不能把业务逻辑堆进命令解析器。
3. GUI、Web 和 App 将来可以存在，但它们只是 Moodify CLI/API 的客户端。
4. 音频文件不是完整工程；工程还包括来源、关系、分析、决策、计划、运行、修订和审批。
5. AI 不应直接拼接不透明效果链；它先提交 intent/plan，由 Moodify 校验、解释、执行和验证。
6. 每次运行都应能回答：为什么做、做了什么、谁或什么决定、使用哪个版本、输出在哪里、如何证明。
7. 后端可以替换，项目与证据不能随工具消失。
8. 自动化不是模拟人工点击，而是把能力变成无界面、确定、可组合、可恢复的协议。
9. 兼容性是数据资产的一部分；升级不能让旧项目、旧命令和历史证据失去解释能力。
10. 重构的成功标准不是目录更漂亮，而是 AI 能安全、稳定、可审计地完成真实音乐工作。
