# 原则种子（三层知识结构）

> 一个项目要有原理层、工程经验层和代码功能层；前两层让代码层不必
> 每次从零出发。

1. 原理回答"为什么必须这样"；经验回答"哪次失败教会我"；代码回答
   "现在是什么"——三层缺一不可，缺了前两层，代码就退化为靠英雄式记忆
   维持的薄结构。
2. 知识必须可核对：每一条原理都有出处，每一条经验都有防复发机制。
   不能核对的知识与遗忘没有区别。
3. 注册表是活的：新条目必须来自真实失败或真实决策，禁止为凑数量编造；
   维护成本低，所以它才能持续存在。
4. 引用是双向的：代码里的规则能向上找到它的经验和原理，任务包能向下
   声明它受哪些原理约束。
5. 本任务只建立知识结构，不修改代码——结构先于内容，层次先于细节。
