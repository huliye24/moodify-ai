# Moodify 歌词意图证据｜原则种子

## 一句话

> **让这首音乐成为它自己。**

## 歌词的位置

> **声音呈现作品的身体，歌词显露作品的指向；Moodify 倾听两者，但不替作者解释作品。**

歌词不是比声音更真实的答案。它可能是叙述者的语言、角色的语言、隐喻、
反讽、重复、遮蔽或有意制造的反差。系统可以记录字面结构，可以保存
创作者授权的声明，可以指出证据之间不一致，但不能夺取解释权。

## 四层证据纪律

1. **事实：** 文件身份、哈希、语言声明、段落、显式标签和可复现重复。
2. **人工声明：** 创作者或 owner 明确提供的主题、视角、情绪方向。
3. **有限推断：** 必须带依据、范围和不确定性，且不得被包装为事实。
4. **未知：** 反讽、隐喻、角色与真实作者关系等无法可靠决定的内容。

## 五条工艺法则

1. **并列而不压制：** 歌词与声音互相照明，任何一方都不能覆盖另一方。
2. **引用而不占有：** 原文只在授权 evidence 中存在，默认表面只给必要关系。
3. **理解而不诊断：** 不把表达对象等同于作者本人，不做心理或身份判断。
4. **冲突而不裁决：** 不一致是一种需要人的证据，不是系统应消灭的错误。
5. **留白而不虚构：** 不知道就保留未知，不用漂亮的情感标签填满作品。

## 反面清单

- 为每首歌词生成一个情绪分数或人格标签；
- 从悲伤词语直接推出应增加温暖、响度或混响；
- 把副歌重复直接解释为最重要的“真实意图”；
- 将第一人称叙述自动视为作者自述；
- 将歌词/声音反差当成缺陷并自动修正；
- 在 CLI、默认摘要或异常里打印整段歌词；
- 自动联网寻找“正确歌词”或补全缺失文本；
- 让歌词功能增加新的默认仪表盘、概念墙或第六叙事中心。

高级秩序不是系统说得更多，而是它知道哪些证据应被保存、哪些关系应被
指出，以及哪些意义必须留给作品和人。
