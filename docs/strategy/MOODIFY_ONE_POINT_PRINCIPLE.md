# Moodify One-Point Principle

**文档编号：MFY-OPP-001**
**状态：战略增量 — 不覆盖 MOODIFY_MUSIC_PROCESSING_INFRASTRUCTURE.md**
**生效日期：2026-08-01**

## 1. 唯一中心

> **让这首音乐成为它自己。**

Moodify 不是增强工具，不是自动母带，不是 AI 混音师。Moodify 是**成全**。

成全的含义：识别作品已经包含但尚未充分显现的秩序，在不损害作品身份的前提下，以克制、可逆、可验证的工艺帮助它完成自身。

## 2. 五条工艺法则

1. **身份先于改善。** 先确认不可失去什么，再讨论能够改变什么。
2. **克制先于展示。** 技术只在帮助判断时出现。存在不等于必须可见。
3. **可逆先于效率。** 不覆盖源，不抹去失败，不以方便换取不可恢复。
4. **诚实先于漂亮。** 知道、推断、不知道、需要人判断——四种状态必须分开。
5. **成全而不占有。** Moodify 提供候选、证据和边界，但不夺取人和作品的最终决定。

## 3. 产品形式原则

操作者首先看到的不是模块、参数、指标或分数，而是：

1. 这首作品是什么？（Essence）
2. 什么必须留下？（Protect）
3. 什么可以被轻轻改变？（Allow）
4. 系统实际做了什么？（Action）
5. 什么仍然需要人来决定？（Entrust）

`must_avoid` 是 Protect 的内在组成：保护作品既包括必须留下什么，也包括绝不能发生什么。它保留在机器合同中，但不另占一个默认叙事中心。

内部复杂性（WSE/MSE/PPE/MRS/Craft/Gate）仍完整保存，但放入可展开的证据层，不进入默认主叙事。

## 4. 语言纪律

默认产品语言不超过 12 个外部词。禁止同义概念并列争夺解释权。内部缩写禁入默认表面。

详见 `LANGUAGE_CANON.md`。

## 5. 反面清单

下列行为不属于 One-Point 跃迁：

- 把"让音乐成为自己"写成 slogan，产品结构不变
- 新增美观界面但堆叠全部指标和内部术语
- 把复杂性藏到无法审计
- 用一个总分代表作品身份
- 自动宣称 improved、release-ready 或 Final
- 以大规模重写制造"焕然一新"的表象

## 6. 与现行战略的关系

本文件是 MOODIFY_MUSIC_PROCESSING_INFRASTRUCTURE.md 的**原理增量**，不覆盖、不替代、不削弱其组织边界、标准生产关系和冷边界。

现行战略定义"Moodify 是什么基础设施"；本原理定义"这个基础设施的唯一动作是什么以及为什么"。

## 7. 歌词意图证据

歌词可以照亮作品的指向，但不高于声音，也不替代创作者声明。Moodify
只记录授权文本的身份、显式结构、可复现重复和人工声明；不从歌词推断
作者心理、身份、立场或作品的“真正含义”。歌词与声音或 One-Point 合同
出现张力时，系统保留冲突并交还 human_owner，不自动裁决。

歌词的技术深度只存在于 evidence。默认表面仍然只有 Essence、Protect、
Allow、Action、Entrust 五个叙事中心。
