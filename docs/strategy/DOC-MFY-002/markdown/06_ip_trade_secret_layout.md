# T6｜专利与商业秘密布局

> 核心原则：公开标准算法只能作为合规基础，不可包装为独占发明。保护对象是**专有组合机制**、**参数校准数据**、**实验衍生方法论**和**特定音源类型的处理工艺**。

## 专利候选清单

### PAT-001: 基于情绪-频率-动态三维约束的音频处理参数自动生成方法

| 属性 | 内容 |
|------|------|
| 对应模块 | `knowledge/craft_chains.py` + `knowledge/emotion_targets.py` |
| 保护对象 | 8 情绪原型 × 6 频段 × 15 参数的三维约束矩阵及其自动推荐算法 |
| 创新点 | (a) 将离散情绪映射为可量化的频谱/动态/空间约束向量，(b) 通过禁忌症机制防止声学不安全的参数组合，(c) 多维约束的加权投影求解算法 |
| 与公开标准的区别 | 公开的情绪-音乐关联研究（如 Juslin & Laukka 2004）描述情绪与声学特征的相关性，但不提供可执行的参数推荐算法。Moodify 的保护点在于**从情绪到具体 EQ/压缩/混响参数的完整映射方法论** |
| 现有技术风险 | 低 — 文献检索未发现将 8 类离散情绪系统性地映射到 15 维音频处理参数空间的专利 |
| 推荐行动 | 优先申请发明专利（中国 + PCT），在 2026 Q3-Q4 完成初稿 |

### PAT-002: 基于波场状态转移矩阵的音频处理效果预测与参数推荐系统

| 属性 | 内容 |
|------|------|
| 对应模块 | `physics/experiments.py` + `physics/b_matrix_parallel.py` |
| 保护对象 | T_EFFECTS 模型：X' = X + B × Δu + ε — 5 维波场 × 15 参数的线性化系统识别与在线校准方法 |
| 创新点 | (a) 将音频处理效果建模为波场状态转移（非传统的输入/输出波形对比），(b) B 矩阵的系统识别实验协议（控制变量 + 交叉验证），(c) 基于岭回归/Kalman filter 的在线校准闭环 |
| 与公开标准的区别 | 控制系统理论中的状态空间模型是公开知识。创新在于**将音频处理效果首次形式化为波场状态转移矩阵**——这一定义本身是新的 |
| 现有技术风险 | 中 — 音频处理中的参数推荐系统存在（如 iZotope Ozone 的 Master Assistant），但基于波场状态转移的具体形式未见公开 |
| 推荐行动 | 2026 Q4 提交发明专利申请。需要先完成 Kalman filter 升级 (ENG-MFY-012) 以扩充权利要求的覆盖范围 |

### PAT-003: 基于多维守恒约束的音频处理安全审计方法

| 属性 | 内容 |
|------|------|
| 对应模块 | `conservation.py` + `safety/bounds.py` + `safety/projection.py` |
| 保护对象 | PHYS-007 四类守恒约束（能量/动态范围/相位/信息）的自动审计与三级 (safe/warning/violation) 告警机制 |
| 创新点 | (a) 处理链的能量归因分解 ΔL_residual = L_out - L_in - ΔL_dynamics - ΔL_spectral，(b) 基于测量噪声 σ 的统计阈值（3σ/12σ）替代硬编码阈值，(c) 审计结果反馈到参数投影的闭环安全机制 |
| 与公开标准的区别 | ITU-R BS.1770 定义响度测量，但不定义处理后的能量归因审计。音频处理的"安全审计"概念本身在文献中少见 |
| 现有技术风险 | 低 — "音频处理的安全审计"作为概念类别在专利检索中几乎空白 |
| 推荐行动 | 2026 Q4 提交发明专利申请，与 PAT-002 可合并或作为分案 |

### PAT-004: 基于谐波/打击乐分离的双链独立处理与融合方法

| 属性 | 内容 |
|------|------|
| 对应模块 | `processing/spectral_chain.py` |
| 保护对象 | HPSS 分离 → 谐波链 EQ/压缩/混响 + 打击乐链 EQ/压缩/限制器 → 加权融合的完整双链处理架构 |
| 创新点 | (a) 对谐波和打击乐分量施加不同的处理策略（谐波注重音色连续性，打击乐注重瞬态保护），(b) 基于源音频特征的自适应融合权重（当前 margin 参数，未来自适应 — ENG-MFY-011），(c) 分离处理后的重合成质量门（防止相位抵消） |
| 与公开标准的区别 | HPSS 分离是公开算法 (Ono 2008)。保护点在于**双链独立处理策略 + 融合机制**，而非 HPSS 本身 |
| 现有技术风险 | 中 — 基于源分离的处理在语音增强领域有先例，但在音乐后期处理中的特定应用组合可能具有新颖性 |
| 推荐行动 | 2027 H1 评估专利申请。需要先完成自适应 margin (ENG-MFY-011) 以加强权利要求 |

## 商业秘密清单

商业秘密保护适用于：(a) 难以从公开产品逆向工程的信息，(b) 专利保护会强制公开的信息，(c) 持续更新、无固定形式的知识。

### TS-001: B 矩阵精确数值

| 属性 | 内容 |
|------|------|
| 对应资产 | PHYS 系列实验的 B 矩阵测量结果 |
| 保护理由 | B 矩阵的精确数值（75 个元素 × 8 种情绪 × 多次校准迭代）是通过真实声学实验测量的——没有实验数据就无法获得。专利申请会强制公开矩阵数值，反而降低了复制难度 |
| 保护措施 | (a) 不写入任何公开文档，(b) 仅存储在加密的校准数据库中，(c) 只通过 API 返回参数推荐结果而不返回 B 矩阵本身 |

### TS-002: 情绪目标向量精确值

| 属性 | 内容 |
|------|------|
| 对应资产 | `knowledge/emotion_targets.py` 中 8 种情绪的完整参数向量 |
| 保护理由 | 这些目标向量是 Moodify 的核心"配方"——如同 Coca-Cola 的配方，一旦公开，竞品可以直接使用而不需要做实验 |
| 保护措施 | (a) 当前已在源码中——应迁移至加密配置文件，(b) API 不返回完整目标向量，(c) 可分发给授权企业客户的运行时仅包含加密版本 |

### TS-003: 禁忌症与缺陷分类法

| 属性 | 内容 |
|------|------|
| 对应资产 | `knowledge/craft_chains.py` 的 contraindications 和 common_defects 数据 |
| 保护理由 | 禁忌症是"不可以做什么"的知识——只能通过处理失败的实验积累。这是一个持续增长的数据库，专利申请无法覆盖其动态性 |
| 保护措施 | (a) 工艺存储器 SQLite DB 加密，(b) 禁忌症更新频率和内容作为竞争优势的内部度量 |

### TS-004: AI 评委校准曲线与权重

| 属性 | 内容 |
|------|------|
| 对应资产 | AI 评委评估结果与实际人类听感评分之间的校准映射 |
| 保护理由 | 校准曲线使 Moodify 的自动化评估能达到接近人类评委的准确度——竞品不知道"如何让 AI 评分像人" |
| 保护措施 | (a) 校准数据不公开——仅在 `calibration/` 加密存储，(b) 随每次 EXP-MFY-010 实验更新 |

### TS-005: 工艺链参数搜索策略与收敛路径

| 属性 | 内容 |
|------|------|
| 对应资产 | 从诊断到推荐的完整决策树——哪些参数先调、哪些后调、何时触发实验重校 |
| 保护理由 | 参数搜索的效率取决于"知道从哪里开始找"——Moodify 的搜索策略是数百次实验的经验结晶 |
| 保护措施 | (a) 搜索策略作为算法配置而非代码注释保存，(b) 不同客户的运行时使用不同的搜索策略变体（使逆向工程更难） |

### TS-006: 特定 AI 模型版本的音频缺陷特征库

| 属性 | 内容 |
|------|------|
| 对应资产 | Suno v3/v4、Udio v1 等 AI 音乐模型的特有缺陷指纹 |
| 保护理由 | 随着 AI 音乐模型快速迭代（每 3-6 个月），其音频缺陷特征也在变化。Moodify 持续追踪这些变化——竞品即使获得昨天的特征库，也无法处理明天的模型 |
| 保护措施 | (a) 缺陷特征库仅内部使用，(b) MRS Open Benchmark 仅公开排名不公开特征，(c) 与 AI 音乐平台建立 NDA 下的缺陷数据共享 |
