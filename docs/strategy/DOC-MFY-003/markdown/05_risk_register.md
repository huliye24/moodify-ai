# DOC-MFY-003｜风险登记表

> 每项风险有：描述、概率 (1-5)、影响 (1-5)、风险值 (P×I)、缓解措施、触发条件、应急预案。
> 风险值 ≥ 15 = 阻断项（必须缓解后才能进入下一阶段）
> 风险值 10-14 = 高风险（需主动监控）
> 风险值 5-9 = 中等（常规监控）

---

## 技术风险

### R-001: RBJ biquad EQ 替换导致 MRS 回归失败

| 属性 | 内容 |
|------|------|
| 描述 | ACU-002 将 FFT EQ 替换为 RBJ biquad 后，由于滤波器形状差异，在 non-flat 参数下处理后的 MRS 与基线差异 > 2.0 分 |
| 概率 | 3 |
| 影响 | 4 |
| 风险值 | **12 (高)** |
| 缓解措施 | 在实验阶段 (AEP-MFY-001) 提前确认 MRS 差异量级。如果差异在 2.0-4.0 分且方向为正（RBJ 更好），修订回归标准至 4.0 分 |
| 触发条件 | AEP-MFY-001 扫频测试完成后，MRS 对比显示差异 > 2.0 分 |
| 应急预案 | 若差异 > 4.0 分且方向为负（RBJ 更差）：检查是否是 pedalboard 的 Q 值定义与 operators.py 不同。可能需要参数映射层（FFT Q → RBJ Q 的标定曲线） |

### R-002: 全通滤波器参数导致低频相位抵消

| 属性 | 内容 |
|------|------|
| 描述 | ACU-001 的全通级延迟 K1=5ms 和增益 g1=0.7 在低频 (< 200 Hz) 可能产生不需要的梳状滤波效应 |
| 概率 | 2 |
| 影响 | 4 |
| 风险值 | **8 (中)** |
| 缓解措施 | 在脉冲响应实验阶段检查低频段的群延迟——如果低频群延迟 > 10 ms，减 g1 至 0.5 |
| 触发条件 | 脉冲响应的低频段 (> 100 Hz) 出现可见的频率响应波动 > 1 dB |
| 应急预案 | 在梳状滤波器前加高通 (cutoff=200 Hz) — 仅对 > 200 Hz 信号应用全通级 |

### R-003: HPSS 残差加回引入可听噪声

| 属性 | 内容 |
|------|------|
| 描述 | ACU-003 的 R 分量加回后，如果 R 主要是噪声（白噪声-like），可能降低 MRS texture 组件 |
| 概率 | 3 |
| 影响 | 3 |
| 风险值 | **9 (中)** |
| 缓解措施 | 实验阶段先分析 R 的频谱特性（白噪声 vs 结构化）。若白噪声占比 > 70%，选择 R_process 策略（低强度处理后加回）而非 R_add_back |
| 触发条件 | R 分量的频谱平坦度 (spectral flatness) > 0.7 |
| 应急预案 | R_process: 低强度压缩 (ratio=1.3) + 低架滤波 (gain=-2 dB on Bass) → 然后加回。如果仍然引入噪声，回退到 R_discard 并标记为"理论假设：残差丢弃的能量通过 makeup gain 补偿" |

### R-004: 7 频段定义更新导致历史诊断数据不可比

| 属性 | 内容 |
|------|------|
| 描述 | ACU-004 的频段定义变更后，新诊断的 S1-S5 参数与历史数据不可直接对比——因为频段边界变了 |
| 概率 | 5 |
| 影响 | 2 |
| 风险值 | **10 (高)** |
| 缓解措施 | 在诊断报告中标注频段版本 (`band_version: "v1.0-7band"`)。同时保留 6 频段计算作为向后兼容（`SpectrumAnalyzer(scale="legacy_6band")`） |
| 触发条件 | 总是触发——这是已知的必然影响 |
| 应急预案 | 提供自动转换脚本：将历史 6 频段数据映射到 7 频段（需要假设频段内能量均匀分布——只是近似） |

### R-005: 真峰值过采样增加处理延迟

| 属性 | 内容 |
|------|------|
| 描述 | ACU-005 的 4x 过采样 + 低通滤波 + 下采样增加的处理延迟可能 > 10 ms |
| 概率 | 3 |
| 影响 | 2 |
| 风险值 | **6 (中)** |
| 缓解措施 | 使用高效的 polyphase 滤波器实现 4x 过采样——延迟应 < 5 ms |
| 触发条件 | 计时测量显示限幅器处理延迟 > 10 ms |
| 应急预案 | 如果延迟不可接受，降为 2x 过采样（对大多数信号的保护效果已达 4x 的 90%） |

## 质量风险

### R-006: 回归测试覆盖不足

| 属性 | 内容 |
|------|------|
| 描述 | v0.4 的修改集中在核心处理路径（operators.py / spectral_chain.py）——测试不足可能导致未被发现的回归 |
| 概率 | 3 |
| 影响 | 5 |
| 风险值 | **15 (阻断)** |
| 缓解措施 | (a) v0.4 启动前，先确认当前 pytest 覆盖率 ≥ 70% (b) VV01 处理路径的每个修改函数必须有对应的 @pytest.mark.v01 测试 (c) MRS 回归测试覆盖所有 8 种情绪 + 6 种风格 |
| 触发条件 | pytest 覆盖率 < 70% |
| 应急预案 | 先写测试，再修改代码——不满足覆盖率不进入 P1 阶段 |

### R-007: P0 修复之间的意外交互

| 属性 | 内容 |
|------|------|
| 描述 | ACU-001 (混响) + ACU-002 (EQ) + ACU-003 (HPSS) 在级联使用时可能产生不可预测的交互效应——单独测试通过但组合测试失败 |
| 概率 | 3 |
| 影响 | 4 |
| 风险值 | **12 (高)** |
| 缓解措施 | 在 P3 回归阶段运行完整处理管线（Scan → Analyze → Diagnose → Process → Validate）的端到端测试——不仅是单元测试 |
| 触发条件 | P3 端到端测试失败 (MRS 差异 > 2.0 分 或 conservation grade = violation) |
| 应急预案 | 二分法定位：修改逐一回退直到回归通过 → 识别出错的交互对 → 修复交互 → 重新验收 |
