# 2026-10-11 — 分轨重制与局部保守修复案例

**性质：** 内部真实案例经验（非 Canon、非已校准 Core 能力）  
**案例目标：** 在已有词曲与分轨基础上完成保守重制，并确认是否可交付。  
**最终状态：** `TECHNICAL_PASS__HUMAN_REVIEW_REQUIRED`  
**CANON_CHANGE：** `NO`

## 1. 本次确认的生产方向

后续歌曲的默认生产对象应是分轨，而不是已经压成一体的成品音乐：

```text
词曲与结构确定
→ 收集/生成分轨
→ 分轨来源与可逆性检查
→ 分轨内部修整
→ 多轨复合
→ 完整技术复检
→ 原版 / A（保守）/ B（充分）审听
→ 人工选定
→ 成品与交付证据
```

这与 Pipeline V4 一致。它不表示“分轨一定更好”；只有在来源、重组质量与复检证据允许时，分轨路径才成立。

## 2. 这次有效的做法

1. **把母带合规和内部精修分开。** 达到响度、真峰和格式标准后，不再通过重复整体 EQ、压缩或增益追求虚假的“更高标准”。
2. **保守版锁定整体方向。** 原 A 版作为 rollback；局部修复不改变整体 tonal balance、空间方向和响度目标。
3. **优先事件级修补。** 对主唱/伴唱只做孤立异常采样修复、小幅逐句电平自动化、轻量齿音控制和边界淡化。
4. **限制干预幅度。** 本案例主唱 ride 上限为 `±0.65 dB`，伴唱为约 `±0.40 dB`；这些是本案例工程默认，不是跨歌曲标准。
5. **处理后独立复检。** 修复版保持 48 kHz / 24-bit、响度与真峰合规，并与保守 A 保持极高波形相关；由此只能证明改动小且技术安全，不能证明听感必然更好。
6. **始终保留原版。** 处理结果不覆盖 A，也不能自动升级为正式交付版。

## 3. 这次失败或风险较高的做法

### 3.1 未校准曲谱不能直接驱动全段修音

Basic Pitch 等自动转录可作为候选判断，但未经音频对齐、音符边界复核和置信度门控的 MusicXML/MIDI，不能直接成为主唱音高修正权威。曲谱适合表达结构，不等于演唱事实。

### 3.2 全段 WORLD 重合成引入可听伪影

把完整人声经过分析—重合成后再做音高修正，可能引入颗粒、气声变化、噪声和辅音损伤。本案例听感退化后已回退。以后默认规则：

- 不因“有 MIDI”就自动重合成人声；
- 先定位确有问题的短事件；
- 原波形优先；只在局部、有置信度且可旁路时处理；
- 处理前后必须做无处理 roundtrip 与局部 A/B；
- roundtrip 不通过时，不允许把结果称为修音改善。

### 3.3 分轨与选定立体声原版并不天然可逆

本案例的 11 根外部分轨与选定原版未通过无处理重组门禁。人类知情覆盖只允许继续实验，不等于 `roundtrip.passed = true`，也不能被后续系统自动解释为深度路径已经验证。

## 4. MATLAB 的正确位置

MATLAB 在本案例中适合承担：

- MusicXML/MIDI 结构检查与音符统计；
- 音频—曲谱对齐实验；
- 分轨与复合版本的频谱、响度、真峰、相位、相关度和差分测量；
- 局部异常事件定位与可视化；
- 参数扫掠、A/B 候选和可重复报告。

MATLAB 输出必须记录输入、版本、参数、指标与产物路径。它不能独立判断“更好听”，不能绕过
Core 的证据门禁，也不能形成第二套 DSP/Judge 权威。经过多案例验证的 MATLAB 方法，应迁入
Moodify Core 的可测试实现；实验脚本本身保留为研究证据。

## 5. 下一首歌的默认策略

1. 从一开始就保存可靠分轨、原始生成版本、BPM/调号、MIDI/曲谱来源和版本。
2. 先做不处理重组，验证分轨能否可信地回到基准；失败即停在实验态。
3. 曲谱只作为结构参考，音高/节奏修改必须由音频证据和置信度支持。
4. 第一轮只产 A（保守）和 B（充分）两个完整候选；不得边听边覆盖。
5. A 优先使用局部、可逆、小幅处理；不要先做全局音色重塑。
6. 对 A、B 和 ORIGINAL 使用同一套复检指标与同一位置切换试听。
7. 机器只给 `TECHNICAL_PASS`、`INCONCLUSIVE` 或 `HUMAN_REQUIRED`；最终选择由人记录。

## 6. 本案例留下的待实现能力

以下仍是 Target，不得写成 Moodify 已具备：

- 来源化的分轨无处理 roundtrip 自动门禁；
- 音频—MIDI/MusicXML 对齐与逐音符置信度；
- 只处理低置信问题片段的局部音高/节奏引擎；
- 分轨级事件检测、逐句自动化与遮蔽诊断；
- 保守/充分两档 Mix Graph 的统一 Core 渲染；
- 手机、耳机、小音箱、单声道的可记录翻译性审听协议。

这些能力进入实现前，应遵循 One Core；MATLAB、FFmpeg 或第三方模型只能作为 Provider/实验来源。
