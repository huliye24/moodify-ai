# NEM-MT-002｜MRS 跑分系统判断标准建立

## 副标题

建立 AI 音乐真实度量化单位，让 Moodify 从主观听感进入工程跑分时代。

---

## 1. 为什么需要 MT-002

MT-001 让 Moodify 可以在云端稳定自动运行，解决的是“系统能不能持续产生数据”。

MT-002 解决的是下一个关键问题：

```text
数据产生之后，我们如何判断声音是否真的变好了？
```

如果没有 MRS，Moodify 的每一次处理结果都只能依靠主观听感、零散描述和人工比较。这样无法形成工程闭环，也无法知道一个版本是否真的比上一个版本更接近真实声音。

MT-002 的意义，是把 Moodify 的声音判断升级为一种可追踪、可比较、可验证、可长期增长的量化单位。

---

## 2. MRS 是什么

MRS 是 Moodify Reality Score。

它不是普通音质分数，不是用户喜好分数，也不是平台流行度分数。

它的核心定义是：

```text
MRS 是 Moodify 用来衡量 AI 音乐真实度的开放跑分单位。
```

MRS 越高，代表 AI 音乐越接近真实声音。

MRS 不设满分。

MRS 可以随着 Moodify 的工程进步、声学研究、参数沉淀和处理工艺升级不断突破。

---

## 3. 为什么不能做成 100 分制

100 分制的问题是，它暗示存在一个静态终点。

但 Moodify 的方向不是“达到满分”，而是让虚拟声波不断接近真实声波。

真实声音本身没有一个简单满分。它涉及动态、空间、纹理、瞬态、情绪、介质、录音链路和播放链路。

因此，MRS 应该像硬件跑分一样：

```text
早期基准可以是 1000
更好的系统可以到 1200
更强的版本可以到 1500
未来极限系统可以继续突破
```

这符合 Moodify 的核心使命：

```text
虚拟声波 → 真实声波
从假到真
现实收敛
```

---

## 4. MRS 的基准锚点

初期建议使用：

```text
基线样本集合的中位数 ≈ 1000 MRS
```

这不是满分，而是校准锚点。

它的作用是让不同版本之间具备比较基础。

例如：

| 情况 | MRS 含义 |
|---|---|
| 低于 900 | 明显存在塑料感、破坏性处理或真实度不足 |
| 约 1000 | 接近当前基线水平 |
| 1100 以上 | 可能明显优于基线 |
| 1200 以上 | 可能进入更强真实度区间 |
| 未来更高 | 代表新的工程突破 |

这些区间不是永久标准，而是早期解释框架。随着样本增多和公式升级，区间可以重新校准。

---

## 5. MRS 主要判断什么

MRS 应尽量基于数学、物理、声学和信号处理，而不是依赖人工投票。

它可以包含以下维度：

| 维度 | 判断内容 |
|---|---|
| 频谱真实度 | 是否过亮、过暗、过平，频带能量是否自然 |
| 动态真实度 | 是否过度压缩，是否存在动态塌陷 |
| 瞬态真实度 | 鼓点、人声边缘、attack 是否清晰自然 |
| 空间真实度 | 声场是否稳定，空间感是否像贴片 |
| 质感真实度 | 高频是否塑料，纹理是否过度平滑 |
| 破坏性惩罚 | 是否通过响度、过亮、过度处理伪造提升 |

Moodify 的目标不是让声音“看起来更刺激”，而是让声音更真实、更有生命感、更接近真实声波结构。

---

## 6. 人类听感的位置

人类听感不是完全不要。

但它应该是 sanity check，而不是主标准。

也就是说：

```text
人类听感用于检查 MRS 是否严重偏离常识；
但 MRS 的主要依据，应来自可重复计算的声学特征。
```

这是因为 Moodify 要建立的是工程单位，而不是审美投票系统。

如果完全依赖听感，MRS 会变成主观喜好；如果完全脱离听感，MRS 可能变成空转公式。

因此，正确关系是：

```text
数学与物理为主，人类听感为辅。
```

---

## 7. MT-002 和 MT-001 的关系

MT-001 是 Runtime 云端运行系统。

MT-002 是 MRS 跑分系统。

它们之间的关系是：

```text
MT-001 负责产生数据
MT-002 负责判断数据
```

只有 Runtime 稳定运行，MRS 才能获得持续样本。

只有 MRS 成立，Runtime 产生的数据才会变成工程反馈，而不只是文件输出。

二者合在一起，Moodify 才会进入真正的工程闭环：

```text
运行 → 处理 → 评分 → 比较 → 优化 → 再运行
```

## 9. Evolution Gate

MT-002 不是一次写完，而是逐步通过 Gate。

| Gate | 目标 |
|---|---|
| Gate 0 | 节点建档完成 |
| Gate 1 | MRS 单位定义完成 |
| Gate 2 | 验证矩阵建立完成 |
| Gate 3 | Runtime 可选评分接入 |
| Gate 4 | 真实 AI 音乐样本基准运行 |
| Gate 5 | MRS 进入 ADOPT 状态 |

这可以避免项目变成“今天改公式，明天改权重”的混乱状态。

---

## 10. 第一阶段执行路线

MT-002 的第一阶段不追求完美公式，而是建立标准。

建议路线：

1. 固化 MRS 的单位定义；
2. 明确开放跑分尺度；
3. 确认无满分原则；
4. 建立验证矩阵；
5. 让 MRS 成为 Runtime 可选列；
6. 用 10-30 首真实 AI 音乐跑第一批基准；
7. 输出第一份 MRS 分布报告；
8. 根据失败项决定 v0.4 的升级方向。

---

## 11. 本节点的完成标准

MT-002 完成，不是因为写出一个公式。

它完成的标准是：

```text
Moodify 拥有一个可以稳定运行、可复查、可比较、可升级的 AI 音乐真实度跑分系统。
```

更具体地说：

- MRS 可以在 Runtime 中作为可选评分列；
- 每个样本都有可追踪评分记录；
- 每次评分有版本号；
- 每次升级有验证矩阵；
- 破坏性处理不会获得虚假高分；
- 高质量样本被破坏后会明显降分；
- 真实样本可以形成长期分布曲线。

---

## 12. 结论

MT-002 是 Moodify 从“能运行”进入“能判断”的关键节点。

MT-001 让 Moodify 活起来。

MT-002 让 Moodify 开始拥有自己的判断力。

当 MRS 成为稳定跑分单位之后，Moodify 的每一次处理、每一次实验、每一次参数调整，都可以被记录、比较和复盘。

这就是 Moodify 从工具软件走向工程生命体的重要一步。
