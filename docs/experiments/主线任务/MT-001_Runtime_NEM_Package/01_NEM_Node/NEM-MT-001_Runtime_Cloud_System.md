## 1. 节点一句话定义

**NEM-MT-001 Runtime 云端运行系统，是 Moodify 的工程地基节点，目标是让 Moodify 在云服务器上稳定、自动、可追踪、可恢复、可长期运行。**

它不是一个单次脚本，也不是一次测试任务，而是 Moodify 后续所有实验、处理、评分、报告、数据沉淀和夜间运行的基础运行层。

---

## 2. 节点定位

Moodify 不能依赖一台本地笔记本，也不能依赖人工盯屏运行。  
MT-001 的使命，是把 Moodify 从“手动运行的软件项目”，升级为“云端自动运行的工程系统”。

该节点完成后，Moodify 应具备以下能力：

1. 云服务器可独立执行音频处理任务；
2. 输入音频可被登记、排队、调度；
3. 系统可按任务队列自动运行；
4. 运行过程可记录日志；
5. 运行结束可生成总结报告；
6. 失败任务可追踪、复查、重跑；
7. 支持后续接入 MRS、Night Worker、Daily Run、批量实验和长期数据沉淀。

---

## 3. 为什么 MT-001 是最高优先级

Moodify 后续所有能力都依赖 Runtime 地基。

没有 Runtime：

- MRS 无法稳定批量验证；
- Night Worker 无法长期无人值守；
- Daily Run 无法成为日常生产系统；
- 真实 AI 音乐样本无法持续积累；
- 工艺参数无法长期沉淀；
- 工程数据无法形成闭环；
- Moodify 无法从“代码项目”进化成“工程生命体”。

因此，MT-001 是 Moodify 主线任务中的第一地基节点。

---

## 4. 节点目标

### 4.1 基础目标

在云端建立一套可稳定运行的 Moodify Runtime 系统，使其能够完成：

```text
输入音频
  ↓
样本登记
  ↓
任务生成
  ↓
队列运行
  ↓
音频处理
  ↓
结果输出
  ↓
日志记录
  ↓
报告生成
```

### 4.2 工程目标

MT-001 不是只追求“能跑一次”，而是追求：

- 可重复运行；
- 可无人值守运行；
- 可批量处理；
- 可记录过程；
- 可复盘结果；
- 可接入评分系统；
- 可扩展为 24h / 36h / 7d 长时运行；
- 可成为后续所有实验的运行基础设施。

---

## 5. 节点边界

### 5.1 本节点负责

1. 云端目录结构；
2. Runtime 配置文件；
3. 输入样本登记系统；
4. 任务队列系统；
5. 批量运行脚本；
6. 日志系统；
7. 最终总结报告；
8. 基础异常处理；
9. 云端运行文档；
10. 与 MRS / Night Worker / Daily Run 的接口预留。

### 5.2 本节点暂不负责

1. 新算法研发；
2. MRS 公式本身优化；
3. 音频处理预设的深度调参；
4. GUI 界面；
5. 用户账号系统；
6. 商业化功能；
7. 移动端 App；
8. 硬件设备；
9. 分布式多服务器调度。

这些属于后续节点。
