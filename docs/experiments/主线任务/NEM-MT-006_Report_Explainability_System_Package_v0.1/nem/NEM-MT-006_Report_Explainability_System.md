# NEM-MT-006｜报告与可解释性系统

**节点主题**：价值显化｜让处理前后差异可见、可解释  
**所属项目**：Moodify  
**所属工程链**：E-Chain-MT｜Moodify 主线工程链  
**节点类型**：NEM｜Node Evolution Molecule｜节点进化分子  
**计划周期**：2026.7 - 2026.9  
**前置依赖**：MRS + 工艺库  
**当前状态**：PLANNED  
**节点优先级**：P0 / 主线关键节点  

---

## 1. 一句话定义

**MT-006 报告与可解释性系统，是 Moodify 的价值显化节点：它把音频处理前后的差异、MRS 分数变化、preset 工艺作用和声音质量改善，转化为人能看懂、AI 能复盘、工程系统能沉淀的报告。**

在 MT-001 到 MT-005 之后，Moodify 已经具备运行、评分、性能、preset 与样本资产的基础。MT-006 要解决的问题是：

> 处理后的音乐到底哪里变好了？为什么变好了？有什么证据？能不能稳定向用户、团队、AI 和未来商业合作方解释？

---

## 2. 为什么 MT-006 很重要

Moodify 不是单纯把音频导入再导出。它真正的商业价值在于让用户相信：

1. 原始 AI 音乐存在可诊断的问题；
2. Moodify 的处理不是随机滤波，而是有工艺逻辑；
3. 处理前后存在可见、可量化、可解释的差异；
4. MRS 的变化可以作为真实性、动态、空间、质感等维度的证据；
5. 每一次处理结果都能沉淀为样本、preset 与报告资产。

如果没有报告系统，Moodify 的很多价值会被隐藏在音频文件内部。用户只能“听一下”，但看不见工程做功；团队只能“感觉变好”，但难以复盘为什么变好；AI 也很难基于历史结果继续优化。

因此，MT-006 是把工程能力转化为用户信任、产品表达、商业交付和技术资产的关键节点。

## 3. 节点在主线中的位置

```text

  ↓

  ↓

  ↓
```

MT-006 解决的是：

> 这些结果如何被看见、解释、交付、复盘和传播。

---

## 4. 核心目标

MT-006 的核心目标是建立一套报告生成与解释系统，使 Moodify 每次处理音频后，可以输出结构化报告。

报告至少应包含：

- 原始音频信息；
- 处理 preset 信息；
- 处理前后 MRS 对比；
- 关键子维度变化；
- 声音问题诊断；
- 处理动作解释；
- 频谱 / 动态 / 空间等可视化差异；
- 工程记录与可复盘字段；
- 用户可读的结论；
- AI 可继续分析的结构化数据。

---

## 5. 报告系统的三层结构

### 5.1 User Report｜用户可读报告

给普通用户、音乐创作者、内容团队看。重点不是技术细节，而是：

- 处理前有什么问题；
- 处理后改善了什么；
- 这首歌更适合什么使用场景；
- 是否值得采用这个版本；
- 还有哪些可以继续处理的方向。

### 5.2 Technical Report｜工程技术报告

给开发者、AI Agent、工程团队看。重点是：

- MRS before / after；
- 子维度变化；
- preset 参数；
- 处理链；
- 耗时；
- 失败与异常；
- 可复现实验信息。

### 5.3 Asset Report｜资产沉淀报告

给样本资产库、preset 工艺库和长期研发系统看。重点是：

- sample_id；
- preset_id；
- run_id；
- report_id；
- MRS 历史；
- 处理 lineage；
- 是否进入优秀案例库；
- 是否成为 preset 调参依据。

---

## 6. 关键判断标准

MT-006 不只是生成漂亮报告，而要满足以下判断标准：

| 标准 | 含义 |
|---|---|
| 可见 | 处理前后差异能够被图表、数值和文字显示出来 |
| 可解释 | 每个主要变化都有声音工程解释 |
| 可追踪 | 报告能追溯到 sample、preset、run、MRS 版本 |
| 可复盘 | AI 和人可以根据报告继续分析问题 |
| 可交付 | 报告可作为用户、团队、商业合作方的交付物 |
| 可沉淀 | 报告结果能回流样本库和 preset 库 |

---

## 7. AEP 工程原子包拆分

MT-006 建议拆分为 10 个 AEP：

| AEP | 名称 | 目标 |
|---|---|---|
| AEP-MT006-001 | 报告信息架构 | 定义报告结构、字段和阅读层级 |
| AEP-MT006-002 | 处理前后对比模型 | 建立 before / after 差异表示方式 |
| AEP-MT006-003 | MRS 解释层 | 把 MRS 和子维度变化翻译成解释文字 |
| AEP-MT006-004 | Preset 效果解释层 | 解释 preset 为什么产生对应变化 |
| AEP-MT006-005 | 可视化差异图 | 生成频谱、动态、响度、空间等图表 |
| AEP-MT006-006 | 用户报告生成器 | 生成面向用户的简洁报告 |
| AEP-MT006-007 | 技术报告生成器 | 生成面向工程和 AI 的详细报告 |
| AEP-MT006-008 | 批量报告系统 | 支持多样本、多 preset 的汇总报告 |
| AEP-MT006-009 | Runtime 报告接入 | 接入 Runtime 自动输出报告 |
| AEP-MT006-010 | 报告质量审计 | 检查报告是否准确、清楚、可追踪 |

## 8. Evolution Gate 进化闸门

| Gate | 名称 | 通过标准 |
|---|---|---|
| Gate 0 | 节点建档 | NEM、AEP、规则、模板完成 |
| Gate 1 | 报告骨架可用 | 单首音频可生成基础报告 |

## 9. 报告输出格式建议

MT-006 应支持多种报告输出格式：

```text
reports/
├── user_report.md
├── technical_report.md
├── report_data.json
├── charts/
│   ├── spectrum_before_after.png
│   ├── loudness_curve.png
│   ├── dynamic_range.png
│   └── mrs_dimension_radar.png
└── export/
    ├── user_report.pdf
    └── technical_report.pdf
```

早期可以先从 Markdown + JSON 开始，不必马上做复杂 GUI。

## 10. 与其他节点的关系

### 与 MT-001 Runtime 的关系

MT-001 提供运行过程和输出目录。MT-006 需要接入 Runtime，在每次处理完成后自动生成报告。

### 与 MT-002 MRS 的关系

MT-002 提供 MRS 跑分标准。MT-006 负责把分数变化解释给人看。

### 与 MT-003 MRS 性能优化的关系

MT-003 保证 MRS 可以批量跑。MT-006 才能在批量生产中稳定生成报告。

### 与 MT-004 工艺库的关系

MT-004 提供 preset 工艺。MT-006 需要解释 preset 的作用、适用场景和处理效果。

### 与 MT-005 样本资产库的关系

MT-005 提供 sample_id、run_id、处理 lineage。MT-006 的报告必须回写到样本资产库，成为长期数据资产。

---

## 11. 节点完成定义

MT-006 被视为完成，不是因为“生成了一份报告”，而是因为：

```text
Moodify 每次处理音频后，都能自动生成可读、可解释、可追踪、可复盘的报告，
让声音处理的价值从音频文件内部显化为用户、AI 和工程系统都能理解的证据。
```

当报告系统可以稳定接入 Runtime，并能基于 MRS、preset、样本资产生成批量报告时，MT-006 可以从 ACTIVE 升级为 ADOPT。

---

## 12. 下一步建议

MT-006 的第一步不应该马上写 PDF 导出功能，也不应该先追求漂亮 UI。

第一步应是：

> 建立报告信息架构，定义一份报告到底应该包含哪些字段、哪些解释、哪些图表、哪些可追踪 ID。

也就是先做：

```text
AEP-MT006-001｜报告信息架构
```

只有报告结构清楚，后续的图表、解释、PDF、HTML、用户界面才不会混乱。

## 节点输入

- 原始音频文件
- 处理后音频文件
- sample_id
- preset_id
- run_id
- MRS before / after
- MRS 子维度
- processing chain
- preset 参数
- Runtime 日志

## 节点输出

- user_report.md
- technical_report.md
- report_data.json
- before_after_charts/
- batch_summary.md
- report_manifest.json

## 不应做的事

- 不要把报告写成纯主观听感。
- 不要让解释脱离 MRS 与 preset 记录。
- 不要在缺少 before / after 数据时强行生成结论。
- 不要让报告成为不可追踪的孤立文件。
