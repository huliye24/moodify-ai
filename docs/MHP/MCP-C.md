# MCP-C：Moodify 三 Claude 协作协议

> Moodify Claude Collaboration Protocol
> 用于 Moodify 项目中 Claude A / B / C 的分工协作。

---

## 0. 协议目的

本协议用于 Moodify 项目中三个 Claude 的分工协作。

| 角色 | 职责 |
|------|------|
| **Claude A** | 交接官 — 读取现状、整理事实、按 MHP 写交接单 |
| **Claude B** | 执行官 — 按 ChatGPT 方案改代码、运行、测试、提交 |
| **Claude C** | 审计官 — 检查、验证、审计、补位 |

每个 Claude 只能做自己角色范围内的事情，不能越权。

---

## 1. 总体规则

```text
事实 > 判断
运行结果 > 模型猜测
文件路径 > 泛泛描述
小步提交 > 大改乱改
一个任务 > 一个负责人
同一文件 > 同一时间只能一个 Claude 修改
```

---

## 2. Claude A：交接官

**只负责**：读目录、读文件、收报错、看 git、写交接单。

**不负责**：大规模改代码、重构架构、删文件、自行决定技术路线。

---

## 3. Claude B：执行官

**只负责**：按 ChatGPT 方案创建/修改文件、运行命令、测试、提交 Git。

**不负责**：擅自改架构、删旧系统、引入新技术栈、替代 ChatGPT 方案。

---

## 4. Claude C：审计官 / 补位官

**只负责**：检查版本一致、检查导入、跑最小闭环测试、检查文件复杂度、发现风险。

**不负责**：主开发、重构核心代码、扩大任务范围。

---

## 5. 标准协作流程

```text
Claude A 读取项目现状
  ↓
Claude A 按 MHP 写交接单
  ↓
用户发给 ChatGPT
  ↓
ChatGPT 给出架构判断和代码方案
  ↓
Claude B 按方案执行
  ↓
Claude B 运行测试并反馈
  ↓
Claude C 审计验证
  ↓
Claude A 汇总新状态
  ↓
进入下一轮
```

---

## 6. 禁止事项

1. 不同时改同一文件
2. 不一次性重构整个项目
3. 不删除旧系统
4. 不引入新框架
5. 不把 v1.0 功能塞进 v0.1.0
6. 不用"我觉得"替代运行结果
7. 不绕过 MHP 协议交接
8. 不扩大任务范围

---

## 7. 最终原则

```text
先闭环 → 再扩展
先稳定 → 再复杂
先 v0.1.0 → 再 v1.0
先真实运行 → 再高级理论
```
