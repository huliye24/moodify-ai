## Claude A 初步判断

### 1. API 切换是最关键的下一步

当前 `/process` 走旧 WorkflowOrchestrator，意味着：
- 每次 API 调用都会触发 RAG 检索、LLM 推荐、参数搜索、安全投影、DB 写入、在线校准——对一个 v0.1.0 API 来说太重
- 如果旧模块（llm/calibration/memory）的依赖出问题，整个 API 就崩了

### 2. API 参数契约需要 ChatGPT 做决策

旧 `/process` 参数是 `emotion`（8 种情绪），新 v01 参数是 `preset`（3 种预设）。两种选择：

**A. 保持 `emotion` 参数名 + 内部映射**：前端不破，但 `emotion` 语义不准确（v0.1.0 只有 3 个预设，不是 8 种情绪）

**B. 改为 `preset` 参数名**：语义准确，但破坏现有 API 契约

**C. 同时支持两个参数**：兼容最好，但增加复杂度

### 3. /sessions 和 /calibration 路由

这两种路由依赖旧系统（DB/校准），在 v0.1.0 中暂时没有对应能力。选项：
- **保留但标记 experimental**：路由还在，失败时降级返回空
- **暂时移除**：只有 `/health` 和 `/process`，最干净
- **保留路由 + 降级逻辑**：路由在，但内部 try/except 降级返回空（当前 sessions.py 已有部分降级逻辑）

### 4. CLI 的 `v01-` 前缀

当前 `moodify v01-analyze` 和旧的 `moodify analyze` 并存。长期来看，v01 应该取代旧命令成为默认。但这一步不急——可以等 API 切完之后再做。
