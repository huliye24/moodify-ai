# MTP：Moodify 智能体任务协议

> Moodify Task Protocol
> 用于把复杂工程目标拆成 Claude、ChatGPT、用户都能稳定理解和执行的任务单元。

---

## 0. 协议目的

MHP 解决"交接问题"。
MCP-C 解决"角色分工问题"。
MTP 解决"任务怎么写、怎么拆、怎么验收"的问题。

---

## 1. 核心原则

```text
复杂目标必须降维
模糊任务必须改写
大任务必须拆小
每个任务只能有一个主负责人
每个任务必须有明确输入、输出、限制和验收标准
```

---

## 2. 任务等级

| 等级 | 名称 | 范围 | 适合角色 |
|------|------|------|----------|
| L0 | 观察任务 | 只看不改 | Claude A |
| L1 | 小改任务 | 1 个文件 | Claude B |
| L2 | 局部功能 | 2-4 个文件 | Claude B 执行，Claude C 审计 |
| L3 | 架构任务 | 路线判断、模块边界 | ChatGPT 设计 |
| L4 | 系统重构 | 多模块、多入口 | 必须拆成多个 L1/L2 |

---

## 3. 标准任务单格式

```text
【MTP 任务单】

【任务编号】    MTP-003-A
【任务等级】    L0 / L1 / L2 / L3 / L4
【任务名称】    一句话
【负责人】      Claude A / B / C / ChatGPT / 用户
【任务背景】    ≤5 行
【任务目标】    完成后应达到的状态
【允许修改】    文件列表
【禁止修改】    文件/目录/行为列表
【输入材料】    需要读取的文件或命令
【执行步骤】    1. 2. 3.
【验收标准】    1. 2. 3.
【失败处理】    停 + 报完整错误 + git status
【输出格式】    交付什么
```

---

## 4. 任务拆解规则

满足以下任一条件必须拆分：

```text
- 修改超过 4 个文件
- 同时改 API 和 CLI
- 需要删除旧系统
- 需要引入新依赖
- 需要修改目录结构
- 需要调整架构判断
```

---

## 5. 角色与任务匹配

| 角色 | 适合任务 |
|------|----------|
| ChatGPT | L3 架构判断、任务拆解、完整文件生成、技术路线 |
| Claude A | L0 观察、整理目录、收集报错、生成 MHP 交接单 |
| Claude B | L1 小改、L2 局部功能、按指定代码替换、运行命令、提交 |
| Claude C | 审计、验证、跑测试、检查版本一致性、检查越权 |
| 用户 | 确认方向、决定取舍、运行 PyCharm、管理 GitHub |

---

## 6. 禁止模糊任务

禁止：优化一下、整理一下、做完整一点、把它做好、重构一下、看看哪里有问题、完善项目、按你的理解改

必须：只修改哪个文件、完成哪个函数、输出什么文件、运行什么命令、通过什么测试

---

## 7. 标准验收规则

不能写"看起来完成了"。必须写可运行的验证命令和预期输出。

---

## 8. 失败处理协议

执行失败时禁止继续猜测式乱改。必须停止并输出：

```text
【MTP 失败报告】
【任务编号】/【失败步骤】/【执行命令】/【完整报错】/【已修改文件】/【git status】/【请求 ChatGPT】
```

---

## 9. 最终规则

```text
大目标不直接执行
复杂任务先降维
每个任务只给一个智能体
每个智能体只做自己能稳定完成的事
每个任务必须可验证
失败立即停止并回报
```

> 不要让智能体理解整个世界。只让它完成一个清楚的小动作。
