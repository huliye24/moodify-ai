# 一、MOOD 是什么

MOOD 是一个开放的 Web3 数字世界 / 协议网络。

MOOD 不是由某一个 App、某一个 Token、某一家公司的产品来定义的。  
它的目标，是建立一个人类、AI Agents、开发者、创作者、节点运营者、研究者与其他参与者都可以进入、贡献、验证并共同建设的开放网络。

MOOD 当前唯一认可的总体结构是：

> **MOOD = WORLD + PROTOCOL + PORTAL**

所有当前主线工作，都必须明确属于以下三层之一，或者直接服务于三层背后的统一 Network 状态。

## WORLD / 世界层

WORLD 是 MOOD 的体验层与文化层。

它回答：

> **“这是一个什么样的地方？为什么值得进入？”**

WORLD 可以包含：

- 视觉与信念；
- 宣言与文化语言；
- 音乐、声音、城市与空间隐喻；
- 世界地图；
- Library / 图书馆；
- Protocol Hall / 协议大厅；
- Builder Workshop / 建设工坊；
- Agent Lab / Agent 实验室；
- Node Station / 节点站；
- Moodify Gate / Moodify 入口。

WORLD 不是协议外面的装饰。

它是人进入 MOOD 世界的第一层界面。

## PROTOCOL / 协议层

PROTOCOL 是 MOOD 的公共规则层。

它回答：

> **“这个世界到底如何运行？”**

当前协议范围只包括：

- Moodify Protocol；
- Proof System；
- Agent Protocol；
- Node Protocol；
- Governance Framework / MIP；
- Economic Rules；
- Treasury Rules；
- Security Model；
- 统一、可版本化、可追踪的公共文档。

协议的存在，不是为了写更多概念。

协议的意义，是让规则可以被阅读、检查、追踪和验证。

一个协议组件不能因为“文档里写了”就算完成。

只有当它的：

> **规则 + 实现 + 证据 + 当前状态**

都可以被检查时，才算真正存在。

## PORTAL / 参与层

PORTAL 是 MOOD 的行动层。

它回答：

> **“我如何进入网络、采取行动、产生贡献，并留下历史？”**

当前 Portal 范围只包括：

- Wallet；
- Passport；
- Assets；
- Rewards；
- Contributions；
- Reputation；
- Agents；
- Nodes；
- 在真实规则存在时对应的 Governance / Rights。

当前认可的身份路径是：

> **Visitor → Connect Wallet → Resident → Contributor → Reputation → Governance / Rights / Rewards**

连接钱包只是入口。

钱包不等于身份。

Passport 才是用户在 MOOD 世界中的历史界面。

Contribution 与 Reputation 必须能够独立于持币数量存在。

## NETWORK / 网络状态

WORLD、PROTOCOL 与 PORTAL 必须最终指向同一个真实 Network 状态。

MOOD 的健康程度，不以以下内容作为核心指标：

- 写了多少代码；
- 做了多少任务包；
- 有多少页面；
- 仓库有多大；
- Token 价格是多少；
- 宣传说得有多宏大。

MOOD 当前认可的 Network Metrics 是：

- Residents；
- Token Holders；
- Developers；
- Creators；
- AI Agents；
- Nodes；
- Contributions；
- Applications；
- MIPs；
- Treasury。

所有数字都必须从真实开始。

> **真实的 1，比虚构的 10,000 更有价值。**

## Moodify

Moodify 是建立在 MOOD 协议之上的第一个真实应用。

它是：

> **Genesis Application / 创世应用**

Moodify 的任务，是证明 MOOD 世界与 Moodify Protocol 可以围绕声音、AI、贡献与协作，产生一个真实可用的产品。

Moodify 不等于整个 MOOD。

## MOOD Token

MOOD Token 是网络的经济媒介。

当前允许的角色只有：

- Settlement / 结算；
- Incentive / 激励；
- Staking / 在存在明确责任、安全或服务约束时的质押；
- Governance / 治理输入；
- Treasury / 金库相关经济协调。

Token 服务于 Network。

不是 Network 服务于 Token。

MOOD 的长期价值必须来自：

- 真实网络；
- 真实应用；
- 真实贡献；
- 真实节点；
- 真实居民；
- 公开规则。

而不是来自：

> **“价格会涨”**

这一假设。

# 二、MOOD 不是什么

这一章存在的目的，是阻止范围失控。

一个想法即使“有用”，只要它不属于当前 MOOD 定义，就不应该进入主线。

## MOOD 不是一个套着网站的发币项目

Token 只是网络中的一个层级。

因此，MOOD 不以以下内容为核心：

- 发币活动；
- Token 价格；
- K 线；
- Holder 增长；
- APY；
- 收益叙事；
- 流动性叙事；
- 投机社区。

价格、交易量和 Holder 数可以作为网络事实被观察。

但它们不能定义 MOOD 的产品进度。

## MOOD 不是“什么都上链”

我们不会因为技术上可以，就把所有东西写上链。

以下行为本身不等于进展：

- 铸造 NFT；
- 铸造 SBT；
- 连接钱包；
- 新部署一个合约；
- 新增加一条链；
- 再创建一个 Token；
- 增加 Staking。

当前身份系统可以继续采用：

> **钱包签名 + Off-chain Profile + 可选链上锚定**

只有当链上实现真正解决以下问题时，才值得增加复杂度：

- 验证；
- 所有权；
- 结算；
- 治理；
- 安全；
- 长期公共状态。

## MOOD 不是 Everything App

AI、音频、Web3、云计算能做的事情很多。

但 MOOD 不需要把所有可能性都做出来。

当前主线不需要成为：

- 通用社交网络；
- 通用聊天产品；
- 通用 AI 助手；
- 通用创作者平台；
- 通用云计算平台；
- 通用开发者市场；
- 通用交易所；
- 通用钱包；
- 通用元宇宙；
- 完整企业软件套件。

如果一个能力不能直接强化：

> WORLD / PROTOCOL / PORTAL / NETWORK / Moodify Genesis Application

就不属于当前范围。

## MOOD 不是历史产品的收容所

过去做过，不等于以后必须保留。

代码已经花了时间开发，也不意味着它天然拥有留在主线的权利。

所有历史产品与实验，只允许四种处理：

- **KEEP / 保留**
- **FREEZE / 冻结**
- **ARCHIVE / 归档**
- **DELETE / 删除**

判断标准不是：

> “我们已经花了多少时间？”

而是：

> **“它是不是当前 MOOD 成立所必需？”**

沉没成本不是产品需求。

## MOOD 不是对未来规模的虚构承诺

我们不虚构：

- 不存在的全球节点；
- 无法验证的居民数量；
- 被包装成真实活动的模拟 Agent；
- 无法公开追踪的 Treasury；
- 没有 Evidence 的 Contribution；
- 不存在的合作与集成；
- 固定收益；
- 保证回报；
- 保证 Token 升值。

如果一个 Network Metric 没有真实来源：

> 就显示 0，或者显示 unavailable。

而不是造一个好看的数字。

## MOOD 不是“买节点就赚钱”

Node 必须长期对应真实网络资源或服务。

节点存在的意义不应该只是：

> “买一个资格。”

如果未来存在 Node Reward，它必须与以下内容之一绑定：

- 真实服务；
- 真实责任；
- 可验证资源；
- 可验证贡献。

## MOOD 不是由 AI 自动控制资金的黑箱

AI Agents 可以：

- 执行任务；
- 分析；
- 研究；
- 验证；
- 协作；
- 贡献。

但 AI Agent 不应该成为不可解释的自动分钱机器。

所有涉及结算的 Agent 行为，都应尽可能遵循：

> **Task → Execution → Evidence → Verification → Contribution Proof → Reputation / Settlement**

以下高风险事项继续保留人工签名和安全门控：

- 私钥；
- Treasury 资金；
- 合约部署；
- 高权限变更；
- 关键参数变更。

# 三、我们现在做什么

当前阶段只做：

> **让白皮书中的 MOOD 在现实中最小成立。**

目标不是补全所有未来想象。

目标是让 MOOD：

> **可以进入、可以阅读、可以参与、可以验证。**

## 1. 一个统一 Network Interface

当前只收敛一个核心入口：

> **crestwavecoin.com**

它必须成为真正的：

> **MOOD Network Interface**

而不是一个普通项目官网。

它必须统一承载：

> **WORLD + PROTOCOL + PORTAL**

并指向同一个 Network 状态。

除非有明确基础设施必要，不再创建多个承担相同职责的平行网站。

## 2. 最小 WORLD

只建设足以让 MOOD 成为“一个地方”的 WORLD。

必须有：

- 统一视觉与信念；
- Manifesto；
- World Map 或等价空间导航；
- Library；
- Protocol Hall；
- Builder Workshop；
- Agent Lab；
- Node Station；
- Moodify Gate。

WORLD 的目标是：

> **建立方向感与意义感。**

不是无限生产视觉装饰。

## 3. 最小 PROTOCOL

只维护一套统一、清晰、可版本化的规则系统：

- Moodify Protocol；
- Proof System；
- Agent Rules；
- Node Rules；
- Governance / MIP；
- Economic Rules；
- Treasury Rules；
- Security。

成熟的协议组件应尽量具备：

- Web 阅读；
- Version；
- 发布日期；
- GitHub Source；
- PDF；
- 实现引用；
- 必要时的合约地址、Chain ID、ABI、配置记录。

同一个概念不得长期存在多套互相重叠的协议定义。

## 4. 最小 PORTAL

当前最重要的是打通这一条：

> **Connect Wallet → Passport → Contribution → Proof → Reputation**

在这条主线成立之后，再接：

- Agents；
- Nodes；
- Rewards；
- Governance / Rights。

Portal 不需要很多空 Dashboard。

宁愿只有一个真正可用的闭环，也不要十个 Coming Soon。

## 5. 真实 Contribution Proof

Contribution 是核心原语。

当前只支持能够产生 Evidence 的贡献类型。

初始类型可以包括：

- Development；
- Creation；
- Research；
- Node Service；
- Verification；
- Governance；
- Community Building。

每一条 Contribution 应尽可能回答：

- 谁完成的；
- 做了什么；
- 什么时候；
- 来源或任务是什么；
- Evidence 在哪里；
- 谁验证；
- 验证状态；
- 最终结果；
- 对应 Hash / Reference。

原则是：

> **Contribution 先于 Reward。**

## 6. 真实 Agents

当前只做真正执行任务的 Agent。

一个 Agent 至少应尽可能具备：

- Identity；
- Role；
- Capability；
- Task；
- Execution Record；
- Output；
- Evidence；
- Verification State；
- Contribution History。

不为了“看起来像 AI 网络”而制造很多空 Agent 类型。

> **1 个真正工作的 Agent 就够了。**

## 7. 真实 Nodes

只建立能够表达真实网络资源的最小 Node 系统。

Node 类型只保留真正被协议和工程支持的角色。

Node 应尽可能具备：

- Stable Identity；
- Operator；
- Role；
- Status；
- Capability；
- Service Evidence；
- Health / Availability；
- Contribution History。

节点数量从 1 开始。

不要因为只有一个节点而觉得不够宏大。

## 8. 最小 Governance 与 Treasury Transparency

治理和资金流只做必要的可追踪能力。

当前需要逐步具备：

- MIP 生命周期；
- Proposal History；
- Protocol Change History；
- 权限边界说明；
- Treasury 地址；
- 资产与资金流入口；
- 重大变更的授权记录。

早期治理允许保留必要管理员。

但必须公开：

> **谁现在拥有什么权限。**

不要假装已经完全去中心化。

## 9. Moodify 只做 Genesis Application

Moodify 当前只证明一件事：

> **MOOD Protocol 可以产生一个关于声音与 AI 的真实应用。**

当前只保留最小有价值路径。

在 Network 没有真正成立之前：

> **Moodify 不继续膨胀成庞大音频软件帝国。**

## 10. Network Observability

Network 页面只展示真实来源。

第一个可接受的状态甚至可以是：

- Residents：1
- Developers：1
- Creators：1
- Agents：1
- Nodes：1
- Contributions：1
- Applications：1
- MIPs：0 或 1
- Treasury：真实状态

0 是可以接受的。

虚构不可以。

Network 页面以后逐步展示：

- Current Network Status；
- Protocol Version；
- Contract Version；
- Latest Contributions；
- Latest MIPs；
- Current Epoch（只有真正存在时）；
- Metrics Definition；
- Snapshot Time。

## 当前阶段的完成条件

现在这个阶段什么时候算完成？

不是任务包做到 030。

也不是代码达到多少万行。

而是一个陌生人可以：

1. 进入 MOOD，并理解自己进入了什么；
2. 阅读协议；
3. Connect Wallet；
4. 建立 Passport；
5. 产生或查看一条真实 Contribution；
6. 查看对应 Evidence / Proof；
7. 查看 Reputation / Contribution History；
8. 查看至少一个真实 Agent 或 Node；
9. 查看真实 Network State；
10. 进入 Moodify Genesis Application。

这条闭环完成以前：

> **所有新的大类产品都属于低优先级。**

# 四、我们拒绝做什么

这一章不是建议。

而是当前阶段的主动拒绝清单。

它存在的目的，是保护：

- 注意力；
- 工程时间；
- Token 预算；
- 项目清晰度；
- 团队认知；
- 架构完整性。

“现在不做”不等于“永远不做”。

它只意味着：

> **不进入当前主线。**

## 我们拒绝做没有白皮书角色的功能

所有新功能必须回答：

> **它服务于 WORLD、PROTOCOL、PORTAL、NETWORK，还是 Moodify Genesis Application？**

如果回答不清楚：

> 不做。

## 我们拒绝在核心闭环成立前继续开新产品

在最小 MOOD 闭环成立以前，不继续扩张：

- Desktop App；
- Mobile App；
- 大型 Workspace；
- Marketplace；
- Enterprise Suite；
- 无关 SaaS；
- 额外消费级产品。

已有实现可以：

> FREEZE 或 ARCHIVE。

但不继续主动扩张。

## 我们拒绝继续把 Moodify 做成一个巨大 Audio Empire

Moodify 是 Genesis Application。

不是吸收所有音频产品创意的容器。

当前不主动扩张：

- DAW-like Workflow；
- Plugin Ecosystem；
- Desktop Audio Suite；
- 全套 Mastering 产品；
- Enterprise Audio Platform；
- Media Marketplace；
- Creator Social Platform。

只保留证明：

> **Moodify / MOOD Protocol 最小真实闭环**

所需要的功能。

## 我们拒绝没有必要的区块链复杂度

不因为“Web3 看起来应该有”就增加：

- 新 Chain；
- 新 Contract；
- Bridge；
- NFT；
- SBT；
- Staking；
- Transaction Tax；
- 新 Token Mechanism。

所有新的链上组件必须回答：

- 它解决什么问题？
- 为什么 Off-chain 不够？
- 安全风险是什么？
- 权限模型是什么？
- Upgrade Model 是什么？
- 数据来源是什么？
- 失败后怎么办？

答不清楚：

> 不做。

## 我们拒绝金融化身份

Passport 与 Reputation 不是持币排行榜。

我们拒绝把：

- 钱多；
- 币多；
- 仓位大；

直接等同于：

- 身份高；
- 声誉高；
- 贡献高；
- 治理合法性高。

MOOD 的身份逻辑优先考虑：

- Contribution Quality；
- Persistence；
- Verification；
- Governance History；
- Reputation。

## 我们拒绝奖励未经验证的活动

原则：

> **没有 Proof，就没有 Contribution Claim。**

> **没有明确规则，就没有 Reward Claim。**

> **没有真实服务，就没有 Node Service Reward。**

> **没有可追踪执行，就没有 Agent Settlement Claim。**

绝不先设计收益，再寻找行为去填收益逻辑。

## 我们拒绝伪造 Network Activity

禁止伪造：

- Residents；
- Nodes；
- Agents；
- Contributions；
- Applications；
- MIPs；
- Treasury；
- Service Capacity。

Test Data / Demo Data 必须明确标记。

并且不能进入公开 Network Metrics。

## 我们拒绝把官网做成 Price Terminal

Network Health 高于 Price。

MOOD 的主叙事不围绕：

- K 线；
- APY；
- “1000x”；
- 固定收益；
- Pump；
- Holder Reward 营销。

市场数据可以存在。

但只能作为事实层存在。

不能成为 MOOD 世界的中心。

## 我们拒绝让 AI 无限扩张 Scope

AI 编程越来越快，不代表产品应该越来越大。

Codex、Cursor、Agents 不得：

- 自创新的产品大类；
- 重复实现已有系统；
- 因为“很容易写”就增加功能；
- 向主线塞大量 Future Placeholder；
- 因为懒得删就保留旧架构；
- 用代码数量制造进展感。

AI 的主要优化目标应改为：

> **Convergence / 收敛**

> **Removal / 删除**

> **Verification / 验证**

> **Simplicity / 简单**

## 我们拒绝因为代码已经写了就保留代码

过去投入了多少时间，不影响今天的判断。

所有现有模块统一进入：

> **KEEP / FREEZE / ARCHIVE / DELETE**

### KEEP

当前 Scope 必需。

### FREEZE

未来可能有价值，但现在停止开发。

### ARCHIVE

保留历史或研究价值，但退出当前架构。

### DELETE

重复、过时、误导、死亡、无人使用、与 Scope 无关。

主线允许大幅缩小。

甚至应该大幅缩小。

## 我们拒绝在当前 Network 还不真实时进入下一轮扩张

下一阶段不是因为：

> “026 做完了，所以自然应该做 027。”

而是因为：

> **当前阶段已经产生真实、可验证结果。**

最终统一原则：

> **现实先于规模。**

> **贡献先于奖励。**

> **规则先于叙事。**

> **Network 先于 Price。**

> **清晰先于扩张。**

# SCOPE FREEZE 最终规则

从本文件生效开始：

任何新的 MOOD 任务包，都必须在文件顶部明确写出：

> **本任务服务于 `MOOD_SCOPE_FREEZE_CN.md` 的哪一个章节、哪一条目标。**

如果无法明确指出：

> **不得进入 MOOD Active Mainline。**

白皮书定义世界。

Scope Freeze 定义边界。

代码只负责实现。

**END OF MOOD SCOPE FREEZE**
