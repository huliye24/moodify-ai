## 0. 本文件是什么

本文件不是普通路线图。

路线图回答：

```text
接下来做什么？
```

本文件回答：

```text
我们正在爬哪座山？
每前进一步，留下什么遗产？
这些遗产如何形成后续攀登的技术势能？
```

Moodify 的长期建设不能只靠一次性的灵感、一次性的 prompt、一次性的代码提交。真正重要的是：每一次推理、每一次实现、每一次实验，都必须沉淀成后续可以继续借力的结构。

技术势能不是代码量。  
技术势能是未来继续向上时，已经不用重新付出的代价。

---

## 1. 山在那里

Moodify 要攀登的高山，不是“做一个能处理音乐的软件”。

这座山的名字是：

```text
可验证、可学习、可复现、可持续进化的情绪显影优化引擎。
```

它的山顶状态不是某一个功能上线，而是一个系统性能力：

1. 软件能理解用户的情绪目标。
2. 软件能诊断当前声音状态。
3. 软件能把诊断状态转化为可执行的处理方案。
4. 软件能记录处理前后发生了什么。
5. 软件能用人耳反馈和代理指标校准自己。
6. 软件能从历史案例中学习，而不是每次从零开始。
7. 软件知道自己的边界，失败时能留下可分析的失败样本。

一句话：

```text
Moodify 的山顶不是更复杂的 DSP 链，而是一个越来越懂声音、懂情绪、懂自己边界的工程生命体。
```

---

## 2. 为什么叫技术势能

势能来自高度。

技术势能来自系统已经爬到的高度，以及这个高度对下一步的支撑能力。

在 Moodify 中，技术势能由这些东西构成：

| 遗产类型 | 说明 | 为什么形成势能 |
|---|---|---|
| 稳定接口 | 后续模块可以直接调用，不用重新理解整套系统 | 降低未来接入成本 |
| 可执行规格书 | AI 和人类都能按步骤实现 | 降低协作损耗 |
| 验证命令 | 每一棒都知道自己有没有爬上去 | 降低回归风险 |
| 实验数据 | 判断方向对错，不靠感觉 | 降低理论空转 |
| 失败样本 | 失败不被浪费，能转成边界知识 | 提高下一轮判断力 |
| 历史案例库 | 新任务可以检索旧经验 | 让系统越用越强 |
| 约束层 | 防止聪明模块越界 | 保留工程可靠性 |
| 接力文档 | 下一棒 AI 不从零开始 | 把 token 推理压缩成工程资产 |

所以，Moodify 的每一步都必须问：

```text
这一步完成之后，后面的人和 AI 是否站得更高？
```

如果答案是否定的，它只是消耗。  
如果答案是肯定的，它才是技术势能。

## 3. 当前山腰：这一轮计划跑完后的基准高度

这一轮计划的目标不是一步登顶，而是建立“可继续攀登的山腰平台”。

当 SPEC-002-REV 与 SPEC-003-RELAY 跑完，Moodify 应该站在这个高度：

### 3.1 已完成的第一根支柱：5D 强度空间搜索

SPEC-002-REV 的核心遗产是：

```text
不再直接搜索 15D 参数，而是在 5D 强度空间中搜索。
```

这一步的技术势能在于：

1. 把维度爆炸压缩到可搜索空间。
2. 把数值优化从 LLM 手里拿回到确定性系统中。
3. 保留 craft_chain_match 和既有工艺知识作为基础资产。
4. 让“情绪目标 -> 状态转移 -> 参数生成”成为可验证链路。

这不是一个小功能。

这是 Moodify 从“预设工具”走向“优化器”的第一块岩壁。

### 3.2 已完成的第二根支柱：LLM 只做擅长的事

SPEC-002-REV 对 DeepSeek 的定位是：

```text
LLM 做自然语言情绪映射与诊断解释，不直接做数值搜索。
```

这一步的技术势能在于：

1. 让用户可以说“像清晨阳光穿过窗帘”，而不是只能选择固定情绪标签。
2. 保留确定性 fallback，API 不可用时系统仍可运行。
3. 避免 LLM 幻觉直接污染 DSP 参数。
4. 把 LLM 从“指挥官”降为“语义解释器”和“诊断叙述者”。

这是一条关键边界：

```text
LLM 负责理解模糊语义。
规则、搜索、约束负责数值决策。
```

### 3.3 下一根支柱：RAG 记忆层

SPEC-003-RELAY 的目标是补上记忆：

```text
第一次处理靠搜索。
第二次处理可以参考历史。
```

这一棒完成后，Moodify 不再只是“会算”，而是开始“会记得”。

它应该留下这些遗产：

1. `processing_history.jsonl`：每次处理的诊断、参数、结果、反馈。
2. `memory/history.py`：历史案例读写与相似检索入口。
3. `llm/prompt_assembler.py`：把诊断、目标、相似案例组装成 RAG prompt。
4. `llm/offline_fallback.py`：没有 API 时仍能用历史统计回退。
5. `DeepSeekClient.recommend_params()`：RAG 增强参数推荐入口。
6. workflow 中明确记录参数来源：`search`、`rag_llm`、`offline_fallback`。

这一步的技术势能在于：

```text
每一次使用都开始变成下一次使用的地基。
```

## 4. 山的分层地图

Moodify 的高山可以分为六层。

### 第一层：可运行的确定性音频管线

关键词：

```text
诊断、工艺卡、DSP、风险门控、可输出音频。
```

这一层回答：

```text
系统能不能稳定处理一首歌？
```

没有这一层，所有 AI 推理都是空中楼阁。

### 第二层：可搜索的情绪状态转移

关键词：

```text
5D 强度空间、LHS 采样、代理评分、多版本选优。
```

这一层回答：

```text
系统能不能不靠固定预设，主动寻找更好的处理方向？
```

这是从工具到优化器的分界线。

### 第三层：可理解的自然语言目标

关键词：

```text
自然语言情绪、DeepSeek、结构化 emotion target、fallback。
```

这一层回答：

```text
用户能不能用人类语言表达目标，而系统仍能落到工程对象？
```

这是从工程内部系统走向创作者产品的分界线。

### 第四层：可积累的历史记忆

关键词：

```text
RAG、处理历史、相似案例、参数来源、离线回退。
```

这一层回答：

```text
系统能不能从过去的处理经验中借力？
```

这是从一次性智能走向持续学习的分界线。

### 第五层：可验证的代理指标

关键词：

```text
EDSR_proxy、盲测、A/B、相关性、失败分类。
```

这一层回答：

```text
系统以为更好的处理，人耳是否真的认为更好？
```

这是 Moodify 最关键的科学地基。

如果代理指标不成立，搜索越强，越可能只是更快地走偏。

### 第六层：可蒸馏的确定性模型

关键词：

```text
合成数据、历史数据、蒸馏、小模型、本地推理。
```

这一层回答：

```text
能不能把昂贵的 LLM 推理压缩成快速、稳定、离线可用的模型？
```

这是从 API 增强系统走向 AI-trained 系统的分界线。

## 5. 每攀登一米必须留下什么

Moodify 的攀登规则：

```text
每前进一步，必须留下能支撑下一步的遗产。
```

任何一棒工作完成时，至少留下五类东西。

### 5.1 决策遗产

必须说明：

1. 为什么这样做。
2. 放弃了什么方案。
3. 当前方案的边界在哪里。
4. 哪些结论来自推理，哪些结论来自实验。

没有决策遗产，下一棒会重复争论旧问题。

### 5.2 接口遗产

必须留下清晰的函数、类、数据结构或 CLI 入口。

例子：

```text
resolve_emotion_from_nl()
search_strength_space()
ProcessingHistory.find_similar()
DeepSeekClient.recommend_params()
```

没有接口遗产，下一棒只能读整片代码。

### 5.3 验证遗产

必须留下可以复跑的验证命令。

验证命令不一定覆盖所有质量问题，但必须回答：

```text
这一棒是否真的跑通？
fallback 是否真的可用？
核心接口是否真的存在？
```

没有验证遗产，技术高度不可确认。

### 5.4 数据遗产

必须留下结构化记录。

例子：

```text
诊断结果
情绪目标
搜索强度向量
最终参数
处理前指标
处理后指标
用户反馈
失败原因
```

没有数据遗产，系统不会变聪明。

### 5.5 失败遗产

失败不能只写“未通过”。

失败样本至少要记录：

```text
输入是什么
期望是什么
实际是什么
可能原因是什么
下次如何复现
它暴露的是实现 bug、指标缺陷、风格边界，还是目标定义错误
```

没有失败遗产，失败只会变成情绪损耗，不会变成技术势能。

## 6. AI 接力的真正用法

多 AI 接力不是让多个模型轮流说漂亮话。

正确模式是：

```text
AI 消耗 token 做推理。
推理必须被压缩成文档、接口、测试、数据或实验结论。
下一棒 AI 从这些压缩物继续向上，而不是重新烧一遍 token。
```

每一棒 AI 开始前，应该先读：

1. `docs/mountain/MOUNTAIN-001_Moodify技术势能之山_第一轮爬升纲领.md`
2. 当前最新 `docs/plan` 规格书
3. 当前最新 `docs/product` 北极星文件
4. 上一棒的接力文档
5. 代码中已经落地的接口
6. 最近一次验证输出

每一棒 AI 结束时，应该留下：

1. 它完成了哪一米。
2. 它留下了什么遗产。
3. 它没有完成什么。
4. 下一个最小可攀登点是什么。
5. 哪些风险需要实验验证。

这样，token 推理才会变成技术势能。

## 7. 本轮完成后的验收门槛

当 SPEC-003-RELAY 跑完，本轮攀登不能只说“代码写了”。

必须满足这些门槛：

1. 无 API key 时，Moodify 仍能完成处理。
2. 有 API key 且有历史案例时，第二次处理能进入 RAG 路径。
3. 日志或 phase 输出中能看出参数来源：`search` 或 `rag_llm` 或 `offline_fallback`。
4. 历史记录文件存在，并且至少包含一次完整处理记录。
5. 相似案例检索可以返回结构化结果。
6. RAG prompt 组装可以独立验证。
7. DeepSeek 参数推荐失败时，不影响主流程。
8. fallback 路径不是摆设，必须可被命令验证。

这八条通过，才算这一轮真正形成山腰平台。

## 8. 下一段山路：不要跳级

这一轮之后，最重要的下一步不是立刻训练模型。

下一步是验证代理指标。

推荐实验：

```text
10 首 AI 生成歌曲
每首 5 个处理版本
共 50 个版本
记录每个版本的代理指标
做 3 到 5 人 A/B 盲测
计算 EDSR_proxy 与 EDSR_true 的相关性
```

判断标准：

```text
相关性 > 0.5：代理指标方向可继续。
相关性 0.3 到 0.5：代理指标需要修正，但方向可能成立。
相关性 < 0.3：搜索目标不可信，必须重构代理指标。
```

这一步是 Moodify 的科学门槛。

如果它成立，后续所有搜索、RAG、蒸馏都有地基。  
如果它不成立，继续堆 AI 只是在错误地形上加速。

## 9. 禁止的攀登方式

为了保持技术势能，以下做法禁止作为主线：

1. 只增加 LLM 调用，不增加可验证遗产。
2. 让 LLM 直接输出无约束 DSP 参数。
3. 为了新功能破坏确定性 fallback。
4. 写了规格书但没有验证命令。
5. 写了实验结论但没有保存数据。
6. 只记录成功样本，不记录失败样本。
7. 每一棒 AI 重新定义方向，不继承上一棒的遗产。
8. 在代理指标未验证前，过早启动模型训练。

Moodify 要的是攀登，不是漂浮。

```text

- ...

本阶段留下的遗产：
- 决策遗产：
- 接口遗产：
```

这个账本的意义是：

```text

```

## 11. 一句话

Moodify 的建设方式应该是：

```text
先看见山，再一米一米攀登；
每一米都留下遗产；
遗产不断叠高，形成技术势能；
技术势能支撑下一次更难的攀登。
```

这座山不是靠一次大模型推理登顶的。

它靠一次次把推理压缩成工程资产、实验资产、数据资产和失败资产，慢慢爬上去。
