## 1. 「相似」的精确定义

### 1.1 四分量相似度（定理4 细化）

```
Sim(C_new, C_hist) =
    0.35 * Sim_diagnosis  # 诊断向量余弦相似度
  + 0.25 * Sim_target     # 情绪目标匹配度
  + 0.25 * Sim_risk       # 缺陷模式相似度
  + 0.15 * Sim_outcome    # 结果可预测性 (有 feedback 时)

Sim_diagnosis: cos(new_vec, hist_vec)

Sim_target:
  1.0  if emotion_code == hist_emotion_code
  0.7  if emotion_category == hist_category
  0.3  if non-conflicting categories
  0.0  if opposing (温柔 vs 废土)

Sim_risk:
  对 17 种缺陷类型, 构建 severity 向量 s ∈ {0,1,2,3}^17
  Sim_risk = 1 - ||s_new - s_hist||_1 / (3*17)  (归一化 L1 距离)

Sim_outcome:
  仅当历史案例有 satisfied 或 EDSR_true:
    若 satisfied=True → 1.0
    若 satisfied=None → 0.5 (中性)
    若 satisfied=False → 0.0 (用于反向排除, 不参与正向)
```

### 1.2 可迁移性判断

```
可迁移 ⇔ Sim ≥ 0.65 AND target_match = True AND risk_compatible = True

target_match: emotion_code 相同 或 category 相同 或 非冲突
risk_compatible: 历史案例的严重缺陷（severity ≥ 2）在当前诊断中也存在
                 (如果历史案例有「高频严重缺失」而当前没有,
                  P15 的处理方式不应照搬)
```

## 2. 失败案例的使用

### 2.1 不参与正向检索

```
find_similar(query):
  candidates = load_all()
  candidates = filter(c.satisfied ≠ False, candidates)  # 排除明确失败
  candidates = score_and_rank(candidates, query)
  return top_k
```

### 2.2 进入反向提示

失败案例作为 LLM prompt 的「避免」信号：

```
## 相似但失败的案例

案例 X (相似度 0.88, 用户不满意):
  使用的参数: P15_high_shelf_gain = +3.5dB
  用户反馈: "太亮了, 高频刺耳"
  教训: 对于 centroid > 3200Hz 的人声, P15 不应超过 +2.0dB
```

### 2.3 失败模式聚类

```
对 50+ 失败案例做聚类:
  特征: 诊断向量 + 目标情绪 + 使用的参数
  聚类: 识别反复出现的失败模式

若某类失败 ≥ 3 例 → 触发规则:
  "当诊断满足 X 条件时, 避免参数 Y 超过 Z"
  这条规则写入约束投影层 (定理5)
```

## 3. 检索质量评估

### 3.1 检索命中后的收益评估

```
对每次 RAG 参与的处理:
  记录: RAG_recommended_params
  记录: 最终选用的参数 (after DSP + 测量选优)
  记录: WHS/EDS 结果

每 50 次 RAG:
  计算 RAG 的"净贡献":
    Δ_EDS_with_RAG vs Δ_EDS_without_RAG (搜索-only baseline)
    若 Δ_EDS_with_RAG > Δ_EDS_without_RAG → RAG 正向贡献
    若持平 → RAG 无贡献 (只是增加延迟)
    若下降 → RAG 负贡献, 需要排查
```

### 3.2 检索漂移检测

```
监控指标:
  avg_similarity: 最近 50 次检索的平均 top-1 相似度
  hit_rate: 检索到案例的比例 (max_similarity > 0.5)

若 avg_similarity 随时间持续下降 → 检索质量退化:
  可能原因: 新歌曲类型超出历史覆盖
  应对: 增加探索 (降低 RAG 权重, 增加搜索权重)

若 avg_similarity 持续上升 → 检索在收敛:
  正效应: 知识库越来越覆盖常见模式
  副作用: 可能过度依赖历史, 忽略新处理方式的可能
  应对: 保留一定比例的随机探索
```

## 4. 防护层实现

```python
def rag_guarded_recommend(query_diagnosis, target_emotion, history):
    similar = history.find_similar(query_diagnosis, top_k=10)

    # Layer 1: 过滤
    valid = [c for c in similar if c.satisfied != False]  # 排除失败
    valid = [c for c in valid if c.emotion_code == target_emotion.code
             or not is_conflicting(c.emotion_code, target_emotion.code)]
    valid = [c for c in valid if check_risk_compatible(c, query_diagnosis)]

    # Layer 2: 相似度门控
    if not valid or valid[0].similarity < 0.5:
        return fallback_to_search()  # 检索不可靠, 回退

    # Layer 3: 置信度评估
    confidence = compute_rag_confidence(valid)
    if confidence < 0.6:
        return blend_with_search(valid, search_results)

    return valid[:5]  # 可信的案例
```
