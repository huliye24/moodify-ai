# EWE 定理 6：失败反证资产定理

**来源**: 母文件 §7 EWE 定理 6
**工程含义**: 失败必须结构化记录, 并进入后续检索、权重修正和理论反证

---

## 0. 定理陈述

失败样本不是废料，而是理论边界的观测点。

### 0.1 形式化

```
FailureCase = (x_raw, g, θ, x_processed, expected_EDSR, actual_EDSR, user_feedback)

每个失败案例:
  - 标记一个「代理指标预测正确但人耳评价相反」的边界点
  - 或标记一个「参数推荐有效但被安全层过度修正」的边界点
  - 或标记一个「风格不匹配导致负迁移」的边界点

失败聚类 = 识别跨风格、跨模型复现的失败模式
失败规则 = 从聚类中提取的可泛化约束
```

---

## 1. 推理展开

### 1.1 失败的五种类型

```
Type 1 — 代理误导: EDSR_proxy 高但人耳偏好低
  → 代理指标失真, 需校准或重构 (→ 定理 2)

Type 2 — 负迁移: RAG 推荐的参数导致效果下降
  → 相似度定义有缺陷, 需重新设计 (→ 定理 4)

Type 3 — 过度投影: LLM/搜索的好参数被安全层过度修正
  → 安全边界过紧, 需情绪特例释放 (→ 定理 5)

Type 4 — 情绪错配: 用户意图 ≠ 映射的情绪原型
  → NL 情绪映射错误, 需改进 prompt (→ SPEC-002-REV Phase 0)

Type 5 — 未知边界: 诊断模式超出历史覆盖
  → 探索不足, 需主动实验 (→ 定理 8)
```

### 1.2 失败聚类方法

```
特征向量: (diagnosis_vector, emotion_code, params_vector)
聚类: K-Means 或 DBSCAN
  目标: 找出失败样本的密集区域 → 这些区域的参数需要避险标签

避险标签: "在诊断区域 D 中, 参数 P 不应超过 Z"
  → 写入约束投影层的组合禁区 (P0-4)
```

## 2. 失败记录的格式

```json
{
  "failure_id": "FAIL-042",
  "type": "proxy_misguidance",
  "diagnosis_snapshot": {"S1": -6.2, "S4": -17.1},
  "emotion_code": "GA",
  "params": {"P15": 3.5},
  "proxy_prediction": 82.0,
  "actual_eds": 45.0,
  "user_feedback": "高频太刺耳了",
  "analysis": "centroid > 3200Hz 的人声对 P15 过度敏感",
  "derived_rule": "centroid > 3200 → P15_max = 2.0"
}
```

## 3. 工程含义

```
1. ProcessingRecord.satisfied=False 的案例自动进入失败分析池
2. 每 50 个失败案例运行一次聚类
3. 从聚类中提取规则 → 写入安全多面体或相似度定义
4. 失败案例不参与正向 RAG 检索 (定理 4)
5. 失败案例在 LLM prompt 中作为「避免」信号 (定理 4 §2.2)
```
