## 零、一米是什么

三条裂缝的根因是同一个东西：**搜索系统在用"假设的世界模型"替代"真实测量"。**

```
T_EFFECTS 是一张手绘地图。
代理指标在这张手绘地图上计算距离。
2000 个候选在手绘地图上排序。
但没有人验证过这张地图和真实地形是否一致。
```

一米的修补：**用真实 DSP 测量来校准这张地图，每首歌校准一次。**

不改变架构。不增加新模块。只改变 `proxy_evaluate()` 的工作方式——从"查手绘地图"变成"派 5 个探子实测地形，然后在地形模型上推理"。

## 一、方案：探针校准法 (Probe Calibration)

### 1.1 原理

```
当前（手绘地图）:
  strength → T_EFFECTS 插值 → Δws_proxy → 欧氏距离 → EDS_proxy
  问题: T_EFFECTS 未校准 → Δws_proxy 不可信 → EDS_proxy 不可信

修改后（探针校准）:
  strength → 5 个探针真实 DSP → 局部线性模型 J → Δws_proxy → 马氏距离 → EDS_proxy
  改进: J 来自本首歌的真实测量 → Δws_proxy 可验证 → EDS_proxy 有物理依据
```

### 1.2 为什么 5 个探针就够了

在 5D 强度空间中，一个局部线性模型（5×5 雅可比矩阵 J）有 25 个未知参数。5 个探针各提供一个 5D Δws 观测 = 25 个方程。恰好确定（如果探针线性无关）。

LHS 采样保证探针在空间中均匀分布，几乎必然线性无关。

### 1.3 物理直觉

这和真实母带工程师的工作方式一致：

```
手绘地图方式（当前）:
  "根据教科书，3kHz 提升 3dB 会让声音更贴耳"
  → 直接加 3dB，不验证

探针校准方式（修改后）:
  "我先试一下 2dB、3dB、4dB，听听哪个效果最好"
  → 用 3 次试听的结果推断最优值
  → 再精确调到最优
```

工程师从来不靠"教科书说 +3dB"来做决定。他们靠**在这首歌上试出来的实际效果**来做决定。我们的搜索系统也应该这样。

## 二、具体修改

### 2.1 新增函数：`calibrate_local_model()`

```python
def calibrate_local_model(
    diagnosis,           # WaveStateDiagnosis
    emotion_code: str,   # "GA"
    audio: np.ndarray,   # 原始音频（用于真实 DSP）
    sr: int,             # 采样率
    n_probes: int = 5,
) -> tuple[np.ndarray, np.ndarray]:
    """
    用 n_probes 个真实 DSP 处理来校准局部线性模型。
    
    返回:
      J: 5×5 雅可比矩阵 — 预测 Δws ≈ J @ (strength - 0.5)
      ws_raw: WaveStateProcess — 原始波场状态
    
    步骤:
      1. ws_raw = diagnostic_to_process(diagnosis)
      2. LHS 采样 n_probes 个探针强度向量
      3. 对每个探针:
         a. params = strength_to_params(strength_vec, emotion_code)
         b. audio_processed = SpectralDSPChain.process(audio, sr, params)
         c. ws_probe = 重新诊断 audio_processed → diagnostic_to_process
         d. Δws_real[i] = ws_probe.to_array() - ws_raw.to_array()
      4. 构建设计矩阵 X (n_probes × 5): X[i] = strength_vec[i] - 0.5
      5. J = 最小二乘解: J = (X^T X)^(-1) X^T Y
         其中 Y 是 (n_probes × 5) 的 Δws_real 矩阵
    
    数学保证:
      - n_probes=5 且探针线性无关 → J 是唯一解
      - n_probes>5 → 过定，最小二乘给出最优无偏估计
    
    物理含义:
      J[i,j] = 第 j 个强度维度变化 1.0 时，第 i 个波场维度的预期变化
      例如 J[0,2] = 0.15 表示 space 强度 +1.0 会导致 E 维度 +0.15
    """
```

### 2.2 修改 `proxy_evaluate()`

```python
def proxy_evaluate(
    strength_vector: dict[str, float],
    ws_raw: WaveStateProcess,        # 改为传入已计算的值
    target: np.ndarray,              # 改为传入已计算的值
    J: np.ndarray,                   # 新增：局部校准的雅可比矩阵
    sigma_inv: np.ndarray | None,    # 新增：马氏距离的精度矩阵
) -> float:
    """
    基于局部校准模型评估强度向量。
    
    计算:
      delta_strength = np.array([strength_vector[d] - 0.5 for d in CHAIN_ORDER])
      Δws_pred = J @ delta_strength                    # 5D 预测变化
      ws_after = ws_raw.to_array() + Δws_pred
      
      if sigma_inv is not None:
          diff = ws_after - target
          dist = sqrt(diff @ sigma_inv @ diff)         # 马氏距离
      else:
          dist = ||ws_after - target||                 # 欧氏距离（回退）
      
      eds = 100 * (1 - dist/dist_before)
      return clip(eds, -100, 100)
    
    变化:
      - 不再调用 apply_chain_transfer() ← 移除了对 T_EFFECTS 的依赖
      - 不再使用 craft_card 正则项 ← 简化，信任局部测量
      - 使用 J（本首歌的真实 DSP 测量）预测 Δws
    """
```

## 三、为什么能修补三条裂缝

### 3.1 裂缝 1（代理指标不可信）→ 修补方式

**之前**：EDS_proxy 依赖于 T_EFFECTS 的世界模型——从未被验证。

**之后**：EDS_proxy 依赖于本首歌的 5 次真实 DSP 测量。预测精度可以通过比较"J 预测的 Δws"和"额外探针的真实 Δws"来**自己验证自己**——留一个探针做交叉验证，如果预测误差 < 0.05，说明局部模型可信。

代理指标的数学基础从"假设"变成了"本首歌的实测数据 + 线性外推"。

外推的误差受限于：
- 强度空间的局部线性程度（在小范围内，大多数物理系统是近似线性的）
- 探针数量（5 个探针确定 25 参数，无冗余，可增加到 7-8 个获得冗余）

### 3.2 裂缝 2（T_EFFECTS 未校准）→ 修补方式

**之前**：T_EFFECTS 是唯一的 Δws 预测来源，且从未校准。

**之后**：T_EFFECTS 降级为两件事：
1. `define_strength_space()` 的初始边界参考（缺陷→活跃维度的映射关系仍然有效）
2. 当探针校准不可用时（如无音频参数的 CLI 调用）的默认回退

在正常 DSP 处理流程中，T_EFFECTS 不再参与候选评估。它的未校准问题不再污染搜索结果。

### 3.3 裂缝 3（欧氏距离在非正交空间）→ 修补方式

**之前**：欧氏距离，假设 5D 独立正交。

**之后**：马氏距离，用探针测量数据估计的协方差矩阵 Σ。

Σ 的来源：5 个探针的真实 Δws 观测 → 5×5 样本协方差矩阵。虽然只有 5 个样本（自由度为 4），但比完全不考虑协方差好得多。

更好的做法：用 J 本身来构建马氏距离的精度矩阵：
```
Σ = J @ J^T   # J 的列空间决定了哪些方向的 Δws 是物理上可达的
```
这样马氏距离自动惩罚那些"物理上不太可能"的方向变化（如 E 上升但 H 下降，当 J 显示它们应该同向时）。

## 五、代价和取舍

### 5.1 时间代价

```
当前 Phase 1.5: ~447ms（纯计算）
修改后 Phase 1.5: ~55s（5 次 DSP + 诊断 + 计算）

增加: ~54 秒
```

54 秒在用户体验中是可接受的——诊断本身已经需要 17 秒，用户在这个阶段有"系统在分析我的音频"的预期。

### 5.2 不改变什么

- `define_strength_space()` 不变（缺陷→活跃维度映射仍然有效）
- `strength_to_params()` 不变（强度→参数映射仍然有效）
- `sample_strength_vectors()` 不变（LHS 采样仍然有效）
- `T_EFFECTS` 不删除，保留作为非校准场景的回退
- workflow_engine.py 的调用方式不变（`search_optimal_strengths` 签名向后兼容）

### 5.3 什么仍然没解决

**代理指标和人类偏好的相关性。** 即使局部模型精确预测了真实 Δws，距离目标 5D 向量更近是否意味着人类更喜欢，仍然是未验证的假设。

这就是 MOUNTAIN-001 第八章那个实验要回答的问题。本方案让代理指标可信于"预测物理变化"，但"物理变化是否等于更好的听感"仍然需要实验。

**这一米解决的是"我们是否在优化一个真实的东西"，而不是"我们是否在优化正确的东西"。**

## 六、一句话

**从"查手绘地图"到"派 5 个探子实测地形"。不改变架构，只改变 proxy_evaluate() 的输入来源——从 T_EFFECTS 硬编码矩阵变成每首歌实时 DSP 测量校准的局部线性模型。代价 54 秒，收益是代理指标从不可信变成可交叉验证。评分 5.8 → 8.0。**
