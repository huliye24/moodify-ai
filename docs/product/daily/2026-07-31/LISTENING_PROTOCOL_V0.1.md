# Moodify 内部盲听协议 v0.1

**日期：2026-07-31**  
**状态：FROZEN / ACTIVE｜VSR-001 已通过**

## 1. 目的

判断处理结果是否在真实听感上优于源版本，并将听感与 MRS、削波、响度、频谱及运行证据分开记录。MRS 只作辅助证据，不单独决定声音好坏。

## 2. 试听材料

- 每组只比较同一源文件的 `before` 与当前运行生成的 `after_matched`；
- `after_matched` 必须由当前运行证据包生成，不复用历史 Inspector 结果冒充当前证据；
- 使用完整曲目，并预先登记 2—3 个关键片段；所有版本使用相同起止点；
- 原始 `after` 只用于技术检查，不进入主观偏好评分。

## 3. 响度匹配

1. 以完整曲目的综合响度为匹配依据；实现暂不支持可靠 LUFS 时，可使用现有 Inspector RMS 匹配，但必须披露方法；
2. `before` 保持不变，只对试听副本施加固定增益；不得压缩、限幅或均衡来完成匹配；
3. 匹配后绝对响度差必须满足 `|Δ loudness| ≤ 0.20 dB`；测量结果至少保留 `0.01 dB` 精度。若测量误差区间跨越 0.20 dB 边界，则标记 `LOUDNESS_UNCERTAIN` 并停止偏好判断；
4. 若增益导致削波，降低两版共同监听电平或重新制作副本，不允许单独限幅其中一版；
5. 评分表必须记录匹配方法、增益值和检查结果。

## 4. 随机与盲法

- 试听文件仅使用随机标签 `A`、`B`，评分者看不到文件名、Preset、指标和波形；
- 每个“曲目 × 候选”使用确定性随机种子生成 A/B 映射，种子写入证据包，映射表由非评分文件单独保存；
- 不沿用固定的 `before → after` 顺序；同一轮在样本间平衡 A/B 身份；
- 每组顺序为 `A → B → A → B`，随后允许自由切换；
- 揭盲必须发生在该轮评分提交之后，评分提交后不得改分，只能追加复核记录。

## 5. 监听条件

- 使用同一耳机或音箱、同一播放设备和固定系统音量；
- 开始前记录设备、环境、试听者、日期与大致监听电平；
- 每连续 30 分钟至少休息 5 分钟；出现听觉疲劳、环境噪声或设备异常时暂停；
- 禁止一边查看技术指标一边评分。

## 6. 评分维度

所有维度都表示“B 相对于 A 的变化”，不表示评分者已经知道哪一个是处理版。采用 1—5 分：`1 B明显差于A`、`2 B略差于A`、`3 持平/不可辨`、`4 B明显优于A`、`5 B显著优于A`。揭盲后再将方向转换为“处理版相对于原版”，不得在揭盲前改分。

| 维度 | 判断问题 |
|---|---|
| clarity | 主体、层次与细节是否更清楚？ |
| tonal_balance | 低中高频是否更自然、不过暗或过亮？ |
| dynamics_transients | 动态和瞬态是否保留，是否泵动或扁平？ |
| spatial_integrity | 宽度、纵深、尾音和中心定位是否稳定？ |
| harshness_control | 刺耳、齿音和疲劳感是否减少？ |
| artifact_control | 是否出现失真、金属感、塑料感、相位或其他伪影？ |
| target_fit | 是否解决该曲目预先登记的主要问题？ |

同时必须填写：强制偏好 `A / B / NO_PREFERENCE`、偏好置信度 `低/中/高`、可定位时间点和自由备注。

## 7. 失败条件

任一硬失败成立，该候选标记为 `FAIL`，即使平均分较高也不能通过：

- 可闻削波、爆音、静音、声道丢失、明显时长错位；
- 新增持续性失真、泵动、金属/塑料伪影或不可接受相位问题；
- 绝对响度差 `> 0.20 dB`，或测量精度不足以判断是否满足门限；
- 身份泄露、顺序未记录或评分后修改原始记录；
- 缺少当前输入哈希、配置、输出、指标或日志中的任一关键证据；
- 对曲目预登记的核心目标造成明显反向变化。

## 8. 单轮判断

- `PREFER AFTER`：无硬失败，强制偏好为处理版，且 `target_fit >= 4`；
- `HOLD`：无硬失败，但偏好为 `NO_PREFERENCE`、置信度低或关键维度冲突；
- `REJECT`：任一硬失败，或处理版被偏好但 `target_fit <= 2`；
- 不因一次内部试听宣称 `PRODUCTION-PROVEN`。

## 9. 试跑后允许修订的范围

v0.1 试跑只允许修正字段歧义、操作顺序和记录缺项。评分尺度、0.2 dB 响度门限和硬失败规则若发生变化，必须升版并说明原因，不回写覆盖旧记录。

## 10. 评分提交与揭盲完整性

1. 评分者只能收到当轮 A/B 文件和评分卡，不得访问映射目录；
2. 揭盲前，记录人必须保存评分卡 SHA-256、A/B 文件 SHA-256、评分者、提交时间和轮次 ID；
3. 提交哈希写入独立的 `submission_commit.json`，之后原始评分卡只读；
4. 揭盲结果和复核只能追加到新的 reveal/review 记录，不能覆盖已提交评分；
5. 任一哈希不一致均标记 `SCORE_INTEGRITY_FAIL`，该轮不得进入偏好统计；
6. 本地内部试跑允许由可信记录人执行上述流程；正式多评分者实验必须使用访问隔离或追加式存储，不能只依赖目录命名。
