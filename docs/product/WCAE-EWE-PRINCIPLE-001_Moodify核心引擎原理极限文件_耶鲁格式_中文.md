# Moodify 核心引擎原理极限文件

## 给影焰实验室的原理、边界、重构方向与极限实验总纲

---

## 第 0 章：文件性质

### 0.1 本文件是什么

本文件是文川院交给影焰实验室的 Moodify 核心引擎**原理极限文件**。

它不替代给工川署的工程规格书。工程规格书回答：

```text
这个系统如何实现？
数据结构是什么？
模块接口是什么？
代码应该怎么拆？
```

本文件回答：

```text
这个系统为什么成立？
哪些原理不可牺牲？
哪些指标代表理论极限？
哪些模块可以重构？
哪些边界一旦突破就会从显影变成失真？
影焰实验室应该怎样通过实验逼近极限？
```

因此，工川署读取 `SPEC-001` 后写代码；影焰实验室读取本文件后重构、压测、消融、组合、反证和逼近极限。

### 0.2 本文件不是什么

本文件不是：

- 工程接口文档。
- 产品 PRD。
- DSP 参数手册。
- 商业演示稿。
- 固定插件链预设。

本文件是**原理约束 + 极限目标 + 实验路线 + 反证协议**。

影焰实验室可以更换实现方式、重构模块、替换库、改写搜索算法、重排实验流程，但不能牺牲本文定义的底层原理。

### 0.3 与 SPEC-001 的关系

```text
SPEC-001：给工川署
  关键词：工程规格、数据结构、API、算法伪代码、任务拆解
  目的：把理论变成可运行代码

PRINCIPLE-001：给影焰实验室
  关键词：原理、极限、反证、重构、实验、边界
  目的：把代码和理论推到性能、听感、稳定性与商业可用性的极限
```

SPEC-001 是工程真相源。  
PRINCIPLE-001 是实验真相源。

## 第 2 章：第一性原理

### 2.1 总原理

Moodify 的全部实验从一个第一性原理出发：

```text
AI 音乐不是成品，而是一个可被诊断、重构、显影的原始情绪波场。
```

对应产品定义：

```text
Moodify = 情绪波场显影器
```

对应工程公式：

```text
不可控 AI 复合波 -> 可控情绪波
```

影焰实验室不能把 Moodify 理解成普通母带工具、音质增强工具或插件预设库。它的对象不是“让音频更好听”，而是：

```text
让原始波场中的情绪胚胎更准确、更清晰、更稳定、更可发布。
```

### 2.2 三层结构

```text
对象：原始情绪波场
方法：波场塑形
目标：情绪显影
```

这三层是影焰实验室的不可拆结构。任何实验如果只优化方法而忘记目标，就会变成普通 DSP 调参。任何实验如果只谈目标而没有 WaveState 记录，就会变成主观审美争论。

### 2.3 最小状态空间

Moodify 的最小状态空间来自 MAIN-051：

```text
WaveState = { Spectrum, Dynamics, Space, Layers, Emotion }
```

在处理引擎中，状态转移使用处理五维：

```text
WS = [E, D, S, T, H]^T

E = 频率均衡度
D = 动态呼吸感
S = 空间层次感
T = 瞬态清晰度
H = 谐波丰富度
```

影焰实验室重构任何模块，都必须保留两件事：

```text
1. 诊断五维用于识别波场问题。
2. 处理五维用于追踪 DSP 状态转移。
```

这两套坐标系可以桥接，不能混为一谈。

## 第 3 章：Moodify 极限目标函数

### 3.1 影焰实验室追求的不是单指标最大化

Moodify 的极限不是：

```text
最大响度
最大低频
最大空气感
最大空间宽度
最大压缩效率
最大处理速度
```

Moodify 的极限是一个多目标约束优化问题：

```text
在不引入过度处理、伪影、疲劳、情绪失真和商业不稳定的条件下，
最大化情绪显影成功率、波场健康提升、可复现性和跨场景稳定性。
```

### 3.2 核心极限目标

```text
Maximize:
  MoodifySuccess
  = WHS_norm(WS_final) × EmotionDevelopmentScore(WS_raw, WS_final, ET)

Subject to:
  Legal(WS_i, ET) = true
  OverprocessingRisk_i < RiskLimit(ET)
  ChainConfidence >= ConfidenceMin
  EDSR_CI excludes 0.50 for publishable craft chains
  Human A/B preference supports processed version
```

其中：

- `WHS_norm` 来自 FORM-050，代表结构健康。
- `EmotionDevelopmentScore` 来自 FORM-051，代表显影效果。
- `ET` 是目标情绪。
- `Legal(WS_i, ET)` 来自 FORM-100，代表每一步状态仍处于目标情绪安全区。
- `OverprocessingRisk` 来自 FORM-055，代表疲劳、伪影和情绪失真风险。
- `EDSR_CI` 来自 FORM-051，代表显影胜率的统计可信度。

### 3.3 北极星指标

Moodify 的北极星指标不是 WHS，而是 EDSR。

```text
EDSR = N_prefer_processed / N_total
```

解释：

```text
WHS 回答：结构是否更健康？
EDSR 回答：处理后情绪是否更符合目标？
MoodifySuccess 回答：结构健康和情绪显影是否同时成立？
```

单独提高 WHS 可能产生“技术自嗨”。  
单独提高主观喜欢度可能产生“玄学自嗨”。  
二者相乘，才逼近 Moodify 的真实极限。

### 3.4 极限分级

| 等级 | 条件 | 影焰处理 |
|---|---|---|
| 实验级 | EDSR 不稳定，CI 包含 0.50 | 只进入研究者模式，不可默认推荐 |
| 可用级 | EDSR > 0.50 且 CI 不包含 0.50 | 可进入创作者模式 |
| 推荐级 | EDSR > 0.70 且 CI 不包含 0.50 | 可作为默认候选 |
| 金牌级 | EDSR > 0.85 且 CI 不包含 0.70 | 可标注为精品工艺链 |

影焰实验室的极限追求，是把核心工艺链从“可用级”推到“推荐级”，再把少数高价值工艺链推到“金牌级”。

## 第 4 章：不可牺牲原则

### 4.1 诊断先于处理

任何 DSP 处理前必须存在诊断记录。

```text
No Diagnosis, No Processing.
```

没有 `WS_raw`、缺陷集合、目标情绪和风险初值的处理，不进入影焰实验记录。

### 4.2 情绪先于参数

同一个参数动作在不同情绪目标下意义不同。

```text
高频提升：
  神圣空灵 -> 空气感
  温柔觉醒 -> 清澈
  都市危险 -> 紧张
  孤独留白 -> 可能破坏距离感
```

因此影焰实验不能以“某参数提升是否好听”为主问题，而必须以：

```text
该参数动作是否帮助目标情绪显影？
```

作为主问题。

### 4.3 状态转移必须可记录

每一步 DSP 都必须记录：

```text
WS_before
theta_i
T_i
WS_after
ΔWS_i
Risk_i
Confidence_i
rollback_decision
```

如果一个处理动作无法记录状态差，它不能进入核心引擎，只能作为人工实验附录。

### 4.4 风险门控不可绕过

任何输出必须通过以下风险门控：

```text
OverprocessingRisk = max(LFR, ArtifactRisk, EmotionDistortionRisk)
```

红色风险输出不能成为推荐版本。  
橙色风险输出只能进入研究者模式。  
黄色风险输出必须带警告。  
绿色风险输出才可进入普通用户候选。

### 4.5 人耳是最终仲裁者

影焰实验室可以自动生成版本、自动计算指标、自动给出报告，但不能让指标完全替代人耳。

所有高价值工艺链必须经过 A/B 或 ABX 测试。

### 4.6 工艺知识必须沉淀

任何成功实验都必须进入工艺沉淀：

```text
实验记录 -> 参数区间 -> 工艺卡 -> 可信度更新 -> 工艺库版本
```

不可复现的“神来一笔”不算 Moodify 能力。Moodify 追求的是可诊断、可解释、可复用、可迭代的工艺。

## 第 5 章：可重构项与不可重构项

### 5.1 可重构项

影焰实验室可以重构：

- 音频分析库。
- DSP 实现方式。
- 参数搜索算法。
- 工艺链组合顺序。
- UI 原型。
- A/B 展示方式。
- 声源分离模型。
- 工艺卡匹配器实现。
- WaveState 的归一化权重。
- 具体情绪工艺链的参数范围。

重构目标是提高：

```text
预测性
稳定性
听感质量
情绪准确度
处理速度
跨设备一致性
实验可复现性
```

### 5.2 不可重构项

影焰实验室不能重构掉：

```text
1. AI 音乐 = 原始情绪波场。
2. Moodify = 情绪波场显影器。
3. 诊断先于处理。
4. 情绪目标统领工程参数。
5. WaveState 是核心状态空间。
6. DSP 步骤必须被视为状态转移。
7. EDSR 是北极星指标。
8. 人耳是最终仲裁者。
9. 风险收益门控必须存在。
10. 成功经验必须进入工艺库。
```

如果某次重构牺牲了以上原则，即使局部指标提高，也不算 Moodify 核心引擎进化。

## 第 6 章：极限实验轴

### 6.1 情绪显影极限

目标：

```text
最大化 EDSR 和 EmotionDevelopmentScore。
```

实验问题：

```text
同一首歌在不同目标情绪下，哪些处理会真正提高情绪准确度？
同一目标情绪下，不同工艺链的 EDSR 差异是否显著？
WHS 提升与 EDSR 提升是否相关？
是否存在 WHS 上升但 EDSR 下降的反例？
```

关键输出：

```text
EDSR 表
EmotionDevelopmentScore 表
A/B 胜率
人耳评语
失败反例
```

### 6.2 波场健康极限

目标：

```text
最大化 ΔWHS，同时不牺牲 EDSR。
```

实验问题：

```text
哪些缺陷对 WHS 扣分最大？
哪些修复对 WHS 提升最快？
WHS 提升是否具有听感可解释性？
五维权重是否需要按目标情绪调整？
```

关键输出：

```text
WHS_raw
WHS_processed
ΔWHS
五维子分变化
缺陷惩罚变化
风险惩罚变化
```

### 6.3 过度处理边界

目标：

```text
找到每条处理链从有效走向失真的临界点。
```

核心公式来自 FORM-055：

```text
Accept(Process) if and only if:
  ΔEmotionScore > λ × OverprocessingRisk
```

实验问题：

```text
低频增强到什么程度开始浑浊？
高频空气感到什么程度开始疲劳？
混响到什么程度从空间感变成假大？
压缩到什么程度从推进感变成动态死亡？
谐波激励到什么程度从温暖变成脏污？
```

关键输出：

```text
Risk curve
LFR curve
Artifact curve
EmotionDistortion curve
rollback point
safe range
```

### 6.4 状态转移可预测性极限

目标：

```text
让 DSP 参数变化对 WaveState 的影响可预测。
```

基础模型来自 FORM-100：

```text
WS(n+1) = saturate(T_i(WS(n), θ_i, ET))
```

线性近似：

```text
WS_out ≈ WS_in + J_i(θ_i, ET) · Δθ_i
```

实验问题：

```text
理论雅可比矩阵与实测状态差是否一致？
哪些参数对 E/D/S/T/H 的影响最稳定？
哪些参数高度依赖歌曲类型？
哪些 DSP 步骤不可预测，应降级为人工实验？
```

关键输出：

```text
J_measured
std_dev
prediction_error
confidence(T_i)
ChainConfidence
```

### 6.5 工艺链匹配极限

目标：

```text
让推荐工艺链越来越接近人耳选择的最佳链。
```

基础模型来自 FORM-101：

```text
MatchScore =
  m1 * DefectCoverage
  + m2 * EmotionTargetFit
  + m3 * WaveStateCompatibility
  + m4 * CraftReliability
  - m5 * RiskScore
```

实验问题：

```text
MatchScore 排名第一的工艺链是否也是人耳 A/B 第一？
缺陷覆盖、情绪适配、波场兼容、可靠性四项中哪一项最能预测胜率？
风险惩罚是否足以阻断危险工艺链？
组合链是否真的优于单链？
```

关键输出：

```text
MatchScore 排名
A/B 排名
rank_correlation
错误推荐案例
权重修正建议
```

### 6.6 商业稳定性极限

目标：

```text
让 Moodify 不只在实验样本上有效，也能在项目组长期使用中稳定。
```

实验问题：

```text
不同 AI 生成模型的输入是否都能稳定诊断？
不同音乐类型是否需要不同权重？
不同播放设备上风险提示是否一致？
短音频和长音频是否都稳定？
批量任务下失败率是否可控？
用户反馈是否能反哺工艺库？
```

关键输出：

```text
跨模型结果
跨风格结果
跨设备结果
批次失败率
回滚率
用户偏好一致性
工艺卡可信度增长
```

## 第 7 章：第一轮极限实验路线

### 7.1 实验 1：基线闭环成立

目的：

```text
验证工川署实现的最小闭环能否完成：
上传 -> 诊断 -> 目标情绪 -> 工艺匹配 -> DSP -> A/B -> 报告。
```

通过标准：

```text
1. 每一步有结构化记录。
2. WS_raw 与 WS_final 可比较。
3. 至少输出 2 个处理版本。
4. 报告包含 WHS、EDSR 准备字段、风险提示和听感解释。
5. 能回滚到原始版本。
```

### 7.2 实验 2：单轴参数扫描

对象：

```text
EQ 低频
EQ 高频
压缩比
混响时间
立体声宽度
谐波激励 drive
```

目的：

```text
为每个参数建立有效区间、风险区间和失真区间。
```

输出：

```text
parameter_range:
  safe_min
  recommended
  safe_max
  risk_start
  reject_start
```

### 7.3 实验 3：处理顺序消融

比较：

```text
频谱 -> 动态 -> 空间 -> 谐波 -> 母带
动态 -> 频谱 -> 空间 -> 谐波 -> 母带
空间 -> 频谱 -> 动态 -> 谐波 -> 母带
谐波 -> 频谱 -> 动态 -> 空间 -> 母带
```

目的：

```text
验证 MAIN-100 的处理顺序逻辑是否成立。
```

重点观察：

```text
返工率
风险累积
相位损伤
EDSR 差异
人耳偏好
```

### 7.4 实验 4：源分离开关实验

比较：

```text
不开源分离：直接全混音处理
轻度源分离：只分人声/伴奏
重度源分离：人声/鼓组/贝斯/其他
```

目的：

```text
验证声源分离是否提升层级控制，还是引入更多伪影和相位风险。
```

判定：

```text
若 ΔEDSR 小于伪影风险增加，不应在普通用户模式默认启用。
```

### 7.5 实验 5：情绪目标远近实验

比较：

```text
原始胚胎情绪接近目标情绪
原始胚胎情绪中等偏离目标情绪
原始胚胎情绪强烈偏离目标情绪
```

目的：

```text
找到 Moodify 可显影边界。
```

结论类型：

```text
可显影：目标与胚胎同向
可修正：目标与胚胎相邻
不建议：目标与胚胎冲突
拒绝：目标要求推翻原始材料
```

### 7.6 实验 6：多版本 Pareto 前沿

每首歌生成至少 5 个候选版本：

```text
V1 保守修复
V2 情绪增强
V3 低风险均衡
V4 激进显影
V5 人耳手调参考
```

绘制 Pareto 前沿：

```text
x = OverprocessingRisk
y = EmotionDevelopmentScore
color = WHS
size = ChainConfidence
```

影焰实验室要找的不是单一最高分，而是最接近商业可用的 Pareto 最优区。

### 7.7 实验 7：跨设备稳定性

设备至少包含：

```text
监听耳机
普通蓝牙耳机
手机外放
笔记本扬声器
车载音响
小型蓝牙音箱
```

目的：

```text
验证身体感、疲劳、空间、低频和响度是否在真实设备上稳定。
```

若某版本只在监听耳机上优秀，在普通设备上失真，则不能进入商业默认版本。

## 第 8 章：失败样本分类

影焰实验室的失败不是废料，而是文川院理论和工川署工程的反证资产。

### 8.1 失败类型

| 类型 | 说明 | 回流位置 |
|---|---|---|
| 理论失败 | 源论文原理不能解释实验结果 | 文川院反证记录或新论文 |
| 指标失败 | WHS、EDSR、LFR 等指标与人耳冲突 | 公式验证系统 |
| 映射失败 | 情绪目标到参数约束的映射错误 | 情绪工艺层 / FORM 权重 |
| 工艺失败 | 工艺链推荐错误或参数越界 | 工艺卡与工艺库 |
| 实现失败 | 代码 bug、DSP 伪影、性能问题 | 工川署 |
| 产品失败 | 用户理解错误、A/B 界面无效、反馈不可信 | 项目组 / 影焰实验室 |
| 商业失败 | 效果好但成本、速度、稳定性达不到交付标准 | 影焰实验室 / 项目组 |

### 8.2 失败记录最小字段

```yaml
failure_id: YY-EWE-FAIL-0001
date: 2026-05-27
audio_id: AUDIO-001
source_model: Suno/Udio/Other
target_emotion: tender_awakening
raw_wave_state: {}
processed_wave_state: {}
craft_chain_id: CC-XX-000
parameters: {}
expected_result: ""
actual_result: ""
metrics:
  whs_delta: 0
  edsr_proxy: 0
  lfr_delta: 0
  overprocessing_risk: 0
human_feedback: []
failure_type: metric_failure
suspected_cause: ""
return_to: 文川院/工川署/影焰实验室/项目组
next_action: ""
```

### 8.3 反证升级规则

```text
单次失败 -> 记录为实验失败样本。
同类失败 >= 3 次 -> 工艺卡风险提示更新。
同类失败 >= 10 次 -> 工川署规则或权重调整。
跨风格、跨模型复现失败 -> 上提文川院反证。
影响商业交付稳定性 -> 影焰实验室建立 P0 阻断项。
```

## 第 10 章：影焰实验室的重构优先级

### 10.1 P0：状态记录与版本系统

没有版本记录，影焰实验无法复现。

必须优先保证：

```text
每次处理都有版本 ID。
每个版本保存 WS_before / WS_after。
每个版本保存参数和风险。
每个版本能回到原始输入。
```

### 10.2 P0：A/B 与人耳评估系统

没有 A/B，EDSR 无法成立。

必须优先保证：

```text
原版、处理版、候选版可盲测。
评分问题区分准确度、清晰度、强度、层次、疲劳、复听意愿。
输出 WinRate 和置信区间。
```

### 10.3 P1：风险收益门控

没有风险收益门控，极限追求会滑向过度处理。

必须实现：

```text
LFR
ArtifactRisk
EmotionDistortionRisk
OverprocessingRisk
Accept(Process) decision
rollback point
```

### 10.4 P1：参数搜索与消融系统

影焰实验室的优势不在手调单个版本，而在高效搜索边界。

必须支持：

```text
单轴扫描
多轴组合
处理顺序消融
工艺链消融
源分离开关实验
跨设备测试
```

### 10.5 P2：工艺卡可信度演化

当实验样本积累后，工艺库要从“研究者经验”升级为“证据驱动资产”。

必须支持：

```text
evidence_count
EDSR_history
reproducibility
risk_incidence
user_preference
version_history
CraftReliability
```

## 第 11 章：商业化前的极限门禁

一个 Moodify 核心功能进入项目组前，必须通过以下门禁。

### 11.1 理论门禁

```text
是否对应第一性原理？
是否服务情绪显影？
是否有源论文或公式支撑？
是否明确边界和反证条件？
```

### 11.2 工程门禁

```text
是否有可运行实现？
是否有输入输出样例？
是否有日志与版本记录？
是否能回滚？
是否通过基础自动化测试？
```

### 11.3 实验门禁

```text
是否有 A/B 结果？
是否有 WHS/EDSR/LFR/风险记录？
是否做过至少一个消融实验？
是否记录失败样本？
是否有可复现参数范围？
```

### 11.4 商业门禁

```text
是否能被普通用户理解？
是否能在常见设备上稳定？
是否有报告解释？
是否有风险提示？
是否能在项目组流程中被反复调用？
```

## 第 12 章：一句话收束

给工川署的 SPEC-001 把 Moodify 写成代码。

给影焰实验室的 PRINCIPLE-001 把 Moodify 推向极限。

影焰实验室的核心任务不是“把效果做得更炫”，而是：

```text
在 WaveState 可记录、EDSR 可验证、LFR 可控制、工艺可沉淀的前提下，
把原始情绪波场推到最清晰、最稳定、最可发布的情绪显影状态。
```

最终判断只有一个：

```text
这个版本是否让原始情绪波场更好地显影，
并且这种显影可以被人耳确认、被指标追踪、被实验复现、被项目稳定调用？
```

如果答案是肯定的，它就是 Moodify 的有效极限。  
如果答案是否定的，再漂亮的波形、再复杂的链路、再高的单项分数，都不是 Moodify 的胜利。
