## 零、修订说明：原方案的四个核心问题

阅读了 `workflow_engine.py`、`state_transfer.py`、`craft_chains.py`、`craft_chain_match.py`、`spectral_chain.py`、`diagnosis/engine.py`、`health_scorer.py`、`emotion_targets.py`、`data_types.py` 全部源码后，发现原方案存在以下结构性问题：

### 问题 1：搜索空间维度选错了

原方案在 **15 维 DSP 参数空间** 做网格搜索。但 `state_transfer.py:60-98` 已经定义了 `T_EFFECTS`——5 个 transfer function（spectrum / dynamic / space / layer / master）各自对波场 5 维状态的影响矩阵。真正决定音频输出的不是 15 个原始参数是 5 个方向的**强度值**。

```
15 参数 → params_to_strengths() → 5 个强度值 [0,1] → apply_chain_transfer() → 5D 波场状态
```

15 维 × 每维 3 个值 = 14,348,907 个组合。要筛到 3000-6500，意味着大部分参数被冻结在推荐值——搜索退化为微调，和 `craft_chain_match` 查表没本质区别。**在 5D 强度空间搜索**：5 维 × 每维 5 值 = 3125 个候选，或者用 LHS 采样 2000 个，覆盖充分且可控。

### 问题 2：T_EFFECTS 代理是循环论证

`state_transfer.py:61-98` 的 `T_EFFECTS` 表本身就是专家经验的百分位数估计（P5/P25/P50/P75/P95）。用它评估参数质量 → 排序 → 选优，等于用同一个经验模型验证自己的输出。搜索结果不可能超越 `craft_chains.py` 里直接写的推荐值。验证标准中"EDS=68.2 > preset baseline 61.4"这个预期改善大概率不会出现。

**代理评估只用于粗筛**，最终评分必须走真实 DSP + 真实诊断测量。

### 问题 3：搜索应该扩展而非替代 craft_chain_match

原方案计划废弃 `craft_chain_match.py`。但它已有完善的 5 子指标评分系统：

```
MatchScore = 0.30*DefectCoverage + 0.30*EmotionTargetFit
           + 0.20*WaveStateCompatibility + 0.20*CraftReliability
           - 0.15*RiskScore
```

加上硬阻断规则（禁忌症匹配）和 `risk_warnings` 惩罚。这套系统应该作为代理评分的**正则项**复用，而不是从零写一个 `EDSR_proxy`。

### 问题 4：DeepSeek 的角色分配反了

原方案让 DeepSeek 做"搜索空间设计"（哪些参数活跃、范围多少）——这是数值优化任务，LLM 不擅长，输出不可靠。

DeepSeek 真正擅长的是 **自然语言 → 结构化情绪映射**。当前 `resolve_emotion()` 靠硬编码 alias 表（`emotion_targets.py:561-578`），输入 `"像清晨阳光穿过窗帘"` 直接抛 KeyError。这才是需要 LLM 的地方。

**角色交换**：
- **LLM 做**：自然语言情绪描述 → 结构化 emotion target（primary, intensity, 5D 理想向量偏置）
- **规则做**：搜索空间定义、参数优化（可验证、可复现、可回退）

## 一、为什么用 DeepSeek API

| 对比维度 | DeepSeek | Claude API | 本地模型 |
|---------|----------|-----------|---------|
| 价格 | ¥1/百万token | $3-15/百万token | 免费 |
| 延迟 | 1-3s | 2-10s | 0.5-5s |
| 中文能力 | 原生最优 | 很好 | 看模型 |
| JSON 结构化输出 | 支持 | 支持 | 不稳定 |
| 部署复杂度 | 零（API调用）| 零（API调用）| 高（需要GPU）|
| 离线可用 | 否 | 否 | 是 |

**决策**: DeepSeek API 作为唯一 LLM 后端。一块 `openai` 库搞定。不做多供应商切换。

```python
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},

    response_format={"type": "json_object"},
```

## 四、阶段划分

### 阶段 A：5D 强度空间搜索（无 LLM，先跑通搜索）

**目标**: 证明"在 5D 强度空间采样 > 单点推荐值"

**核心洞察**: 不在 15D 参数空间搜索。利用现有的 15 参数 → 5 强度映射（此映射逻辑已隐含在 `spectral_chain.py` 的 `_harmonic_params` / `_percussive_params` 中），直接在 5D 强度空间采样，然后用 `T_EFFECTS` 预估效果。

**新增 1 个文件 + 1 个 `__init__.py`**:

```
optimizer/search.py  (~180行)

  核心函数:

  1. define_strength_space(defects, emotion_code)
     基于缺陷类型 + 情绪代码,确定 5 个 transfer 维度的搜索范围
     
     规则:
       - 如果缺陷分类中有"频谱"类缺陷 → spectrum 维范围 [0.2, 0.8]
       - 如果情绪目标需要大空间感 (SE/CN) → space 维范围 [0.4, 0.9]
       - 每个情绪代码从 craft_chains.py 读取 risk_warnings 作为边界约束
       - 活跃维度的范围 = [P10, P90]，冻结维度保持推荐值
     
     输出: {
         "spectrum":  (0.2, 0.8),
         "dynamic":   (0.2, 0.8),
         "space":     (0.4, 0.9),
         "layer":     (0.1, 0.7),
         "master":    (0.3, 0.7),
     }

  2. sample_strength_vectors(space, n=2000)
     使用 scipy.stats.qmc.LatinHypercube 在 5D 空间采样
     - 保证每维均匀覆盖
     - 2000 个样本已足够代表性
     
     输出: list[dict] — 每个 dict 是 {"spectrum": 0.xx, "dynamic": 0.xx, ...}

  3. proxy_evaluate(strength_vector, ws_raw, emotion_target, defects)
     对单个强度向量预估最终效果:
     
     计算链 (全部使用已有代码):
       ws_raw = StateTransferEngine.diagnostic_to_process(diagnosis)
       ws_proxy, _ = StateTransferEngine.apply_chain_transfer(
           ws_raw,
           chain_types=["spectrum", "dynamic", "space", "layer", "master"],
           dsp_strengths=list(strength_vector.values()),
           emotion_target=emotion
       )
       eds_proxy = HealthScorer._compute_eds_from_vectors(ws_raw, ws_proxy, emotion)
       
       # 复用 craft_chain_match 评分作为正则项 (惩罚违反风险规则)
       craft_penalty = compute_craft_penalty(strength_vector, craft_card)
       
       score = eds_proxy - 0.1 * craft_penalty
     
     输出: float

  4. strength_to_params(strength_vector, emotion_code)
     将 5D 强度向量反推为 15 个 DSP 参数
     
     反推逻辑:
       - 从 craft_chains.py 读取该情绪的 rec/min/max
       - spectrum 强度 → 插值 P01-P05 + P14-P15 (在 min-rec-max 间)
       - dynamic 强度 → 插值 P06-P09
       - space 强度 → 插值 P10-P12
       - layer 强度 → 插值 P13
       - master 强度 → 固定为推荐值 (P06 ratio 微调)
     
     输出: dict[str, float] — 15 参数值

  5. search_optimal_strengths(diagnosis, emotion_code, top_k=3)
     主入口:
       1. define_strength_space()
       2. sample_strength_vectors()
       3. 对每个向量 proxy_evaluate()
       4. 排序, 取 top-k
       5. 对 top-k 分别调用 strength_to_params()
     
     输出: list[tuple[dict, dict, float]]
           [(strength_vector, params_dict, proxy_score), ...]
```

**修改 1 个文件**:

```
orchestration/workflow_engine.py  (~40行改动)

  process() 方法中:
    Phase 1 之后 → 调用 search_optimal_strengths() → 得到 top-3 (强度向量 + 参数)
    Phase 3 改为: 对 top-3 参数分别调用 SpectralDSPChain.process()
    Phase 6 之后 → 对每个版本重新诊断 → 测量 WHS/EDS → 选最优 → 输出
```

**验证标准**:
```bash

#   Phase 1.5: 5D 强度空间搜索
#     活跃维度: spectrum[0.2,0.8], dynamic[0.2,0.8], space[0.4,0.9]
#     LHS 采样: 2000 候选, 评估耗时 0.3s
#     Top-3 代理分: [72.5, 68.1, 65.3]
```

**设计要点**:
- `proxy_evaluate()` 用 T_EFFECTS 做粗筛——排序只需要相对顺序正确，不需要绝对值准确
- 真实评分由 Phase 6 后的诊断测量决定——代理只是用来选 top-3 走真实 DSP
- `craft_penalty` 确保违反 `risk_warnings` 的候选被惩罚（如 "压缩比 > 2.5:1"）

### 阶段 C：记忆闭环（推迟执行）

**前置条件**: 阶段 A 已积累 ≥ 50 条真实处理记录。

**原因**: 少于 50 条记录时，余弦相似度检索的命中质量不可靠。诊断向量空间中的"邻近"不一定对应处理需求的"相似"——两首歌可能有相似的频谱特征但需要完全不同的处理（受风格、编曲、用户主观偏好影响）。需要积累足够数据来验证"诊断相似 → 处理相似"这个假设是否成立。

**新增 1 个文件**:

```
memory/history.py  (~120行)

     save(record: ProcessingRecord)
```

## 六、T_EFFECTS 代理的局限性声明

`state_transfer.py:61-98` 的 `T_EFFECTS` 表是对 5 个 transfer function 效应的经验估计。用它做代理评估存在固有偏差：

| 代理能做的 | 代理不能做的 |
|-----------|-------------|
| 区分差异大的候选 (ΔEDS > 10) | 区分微调候选 (ΔEDS < 3) |
| 排除违反风险边界的候选 | 捕捉参数间非线性交互 |
| 给出候选的大致排序 | 预估真实的音质感知 |

因此，代理评估**只用于从 2000 个候选粗筛到 top-3**。最终选择完全由真实 DSP + 真实诊断测量决定。如果阶段 A 跑下来发现代理排序和真实排序相关度 < 0.6，则需要考虑用真实 DSP 评估更多候选（如 top-20 而不是 top-3）。

## 八、工程原则

1. **每个阶段独立可验证。** 阶段 A 不需要 DeepSeek。阶段 B 有完整 fallback。阶段 C 有前置数据门槛。

2. **DeepSeek 做语义，规则做数值。** LLM 处理"像清晨阳光"→情绪映射。搜索空间和参数优化永远由规则驱动。各司其职。

3. **DeepSeek 是增强，不是依赖。** API 挂了、没配 key、超时 → 自动回退。软件永远可用。

4. **先跑通，再变聪明。** 阶段 A 用 LHS 采样证明"搜索 > 单点"。如果代理排序与真实排序相关度低，调整评估函数，不引入 LLM 救场。

5. **复用已有资产。** `T_EFFECTS`、`craft_chain_match` 评分、`risk_warnings` 基础设施都在，不要从零写。

6. **等待数据，而非预判数据。** 记忆闭环需要真实使用数据来验证"诊断相似 → 处理相似"假设。在此之前不做。
