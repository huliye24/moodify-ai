# SPEC-004-REV：探针校准修正 — 单探针验证 + 异步校准

**时间**: 2026-05-28
**替换**: SPEC-004 原版
**修订原因**: 原版 5 探针校准耗时 15-60s，处理本身只要 3s。时间倒挂。

---

## 0. 原版问题

| 问题 | 根因 | 后果 |
|------|------|------|
| 校准比处理慢 5-20 倍 | 5 探针×(DSP+WAV I/O+重诊断) | 15-60s 开销, 用户体验崩溃 |
| 临时 WAV 编解码 | DSP numpy→WAV→读回→numpy | 每探针浪费 0.5s+ |
| 全量诊断不必要 | 探针只需 5D 向量, diagnose_quick 算了 18 参数 | 每探针浪费 1-2s |
| 每首歌都校准 | 不管 T_EFFECTS 是否已经够准 | 大多数歌白花时间 |
| 校准结果不缓存 | 同一首歌再处理时重新校准 | 重复浪费 |

---

## 1. 修正方案

**三层设计：**

```
Layer 1 (默认, 0s): 纯 T_EFFECTS — 不校准, 直接搜索
    ↓ 用户主动触发或系统检测异常
Layer 2 (可选, ~3s): 单探针验证 — 1 次 DSP+轻量诊断, 测 T_EFFECTS 偏差
    ↓ 验证偏差 > 阈值
Layer 3 (异步, 后台): 5 探针岭回归校准 — 存到缓存, 下次同歌/同类歌可用
```

### 1.1 Layer 1: 零开销默认

搜索直接用 T_EFFECTS 代理评估。`calibrate()` 不被调用。延迟 = 0。

这是 80% 歌曲的正确选择——T_EFFECTS 的经验矩阵对典型 AI 音乐是够用的。

### 1.2 Layer 2: 单探针验证（~3s）

当用户选择「精确模式」或系统检测到异常诊断模式时触发。

只跑 **1 个探针**：
```
1. 取 search_optimal_strengths 的 top-1 强度向量作为探针
2. DSP 处理 → 内存中的 numpy 数组（不写 WAV）
3. 轻量重诊断（只算 5D 向量, 不算 18 参数和缺陷分类）
4. 对比: actual_Δws vs T_EFFECTS_predicted_Δws
5. 偏差小 → 确认 T_EFFECTS 可靠, 返回置信度 > 0.8
6. 偏差大 → 标记异常, 触发 Layer 3 (异步)
```

**轻量重诊断**（新增函数, 替代 `diagnose_quick` 用于探针验证）:

```python
def diagnose_lightweight(audio: np.ndarray, sr: int) -> np.ndarray:
    """只计算 5D WaveState 向量, 不计算 18 参数详情。
    
    跳过: 缺陷分类、WHS 评分、质量门、完整 18 参数提取
    只做: STFT → 5 维度各算 1 个代表性指标 → diagnostic_to_process → (5,)
    
    目标: < 0.5s (vs diagnose_quick 的 2-3s)
    """
```

具体实现: 从 `diagnosis/engine.py` 的 5 个维度中各取 1 个最快计算的参数（S3_MidClarity, D1_LRA 用简化版, SP1_Correlation, L3_DrumDetect 用简化版, E3_FatigueRisk 用简化版），跳过完整的 pyloudnorm 和 Schroeder RT60。

### 1.3 Layer 3: 异步岭回归校准（后台）

仅当 Layer 2 验证偏差 > 阈值时触发。

- 不阻塞主流程。主流程返回 T_EFFECTS 结果给用户。
- 后台跑 5 探针岭回归校准（SPEC-005-REV 的修正版 calibrate）。
- 结果存入 `outputs/calibration_cache/{diagnosis_hash}.npz`。
- 下次同一首歌（或诊断向量余弦 > 0.95 的歌）再处理时，直接读缓存。

**修改 2**: 新增 `diagnose_lightweight()`。

```python
def diagnose_lightweight(audio: np.ndarray, sr: int) -> np.ndarray:
    """轻量重诊断 — 只计算 5D WaveState, 不做完整 18 参数提取。
    
    每维度取 1 个最快计算的代表性参数:
      E: S3_MidClarity (STFT 中频能量比, < 0.1s)
      D: 简化 LRA (RMS 分段落差, 不用 pyloudnorm, < 0.1s)
      S: SP1_Correlation (左右声道相关, < 0.05s)
      T: 简化瞬态检测 (帧间 RMS 峰值比, < 0.05s)
      H: 简化 FatigueRisk (高频粗糙度估计, < 0.1s)
    
    总计: ~0.5s (vs diagnose_quick 的 2-3s)
    """
    from moodify.orchestration.state_transfer import StateTransferEngine
    
    # 使用已有的 metrics 模块的快速计算
    from moodify.diagnosis.metrics import SpectrumAnalyzer, DynamicsAnalyzer, SpaceAnalyzer
    
    spec = SpectrumAnalyzer()
    dyn = DynamicsAnalyzer()
    spa = SpaceAnalyzer()
    
    # 频谱: 中频清晰度 (只用 STFT, 不需要 full 18-param)
    stft_data = spec.compute_stft(audio, sr)
    mid_clarity = spec._mid_clarity_fast(stft_data)  # S3 简化版
    
    # 动态: 简化 LRA (段落 RMS 分位数差, 不调 pyloudnorm)
    rms_segments = dyn._segmented_rms(audio, sr, n_segments=10)
    lra_simple = float(np.percentile(rms_segments, 95) - np.percentile(rms_segments, 5))
    lra_norm = min(lra_simple / 15.0, 1.0)
    
    # 空间: 左右声道相关性
    corr = spa._channel_correlation(audio)
    
    # 层级: 简化瞬态检测
    transient_score = dyn._transient_density(audio, sr)
    
    # 情绪: 简化疲劳风险 (高频能量比)
    fatigue_simple = spec._hf_roughness_fast(stft_data)
    
    # 桥接到 5D
    E = max(0.0, min(1.0, mid_clarity))
    D = max(0.0, min(1.0, lra_norm))
    S = max(0.0, min(1.0, 1.0 - corr))
    T = max(0.0, min(1.0, transient_score))
    H = max(0.0, min(1.0, 1.0 - fatigue_simple / 100.0))
    
    return np.array([E, D, S, T, H], dtype=np.float64)
```

**修改 3**: `calibrate()` — 用 `diagnose_lightweight` 替代 `diagnose_quick`，去掉临时 WAV 文件。


### 2.2 新增 `optimizer/calibrate.py` — `validate_te()`

```python
def validate_te(
    diagnosis,
    audio: np.ndarray,
    sr: int,
    emotion_code: str,
    top_strength: dict[str, float],
) -> dict:
    """Layer 2: 单探针验证 T_EFFECTS 准确性。
    
    用搜索 top-1 的强度向量做一次真实 DSP+轻量诊断,
    对比 T_EFFECTS 的预测偏差。
    
    Returns:
      {
        "te_reliable": bool,        # T_EFFECTS 是否可信
        "deviation": float,         # 预测 vs 实际的 5D 偏差
        "actual_delta": np.ndarray, # (5,) 实际 Δws
        "predicted_delta": np.ndarray, # (5,) T_EFFECTS 预测 Δws
        "elapsed_ms": float,
      }
    """
    t0 = time.perf_counter()
    
    from moodify.orchestration.state_transfer import StateTransferEngine
    from moodify.knowledge.emotion_targets import get_ideal_process_vector
    
    ws_raw = StateTransferEngine.diagnostic_to_process(diagnosis).to_array()
    
    # T_EFFECTS 预测
    engine = StateTransferEngine()
    ws_proc = StateTransferEngine.WaveStateProcess(
        E=float(ws_raw[0]), D=float(ws_raw[1]),
        S=float(ws_raw[2]), T=float(ws_raw[3]), H=float(ws_raw[4]),
    )
    chain_strengths = [top_strength.get(d, 0.5) for d in CHAIN_ORDER]
    ws_te, _ = engine.apply_chain_transfer(ws_proc, CHAIN_ORDER, chain_strengths, emotion_code)
    predicted_delta = ws_te.to_array() - ws_raw
    
    # 真实 DSP + 轻量诊断
    processed = run_probe_dsp(audio, sr, top_strength, emotion_code)
    ws_actual_5d = diagnose_lightweight(processed, sr)
    actual_delta = ws_actual_5d - ws_raw
    
    # 偏差
    deviation = float(np.linalg.norm(actual_delta - predicted_delta))
    te_reliable = deviation < 0.08  # 5D 空间中的偏差阈值
    
    return {
        "te_reliable": te_reliable,
        "deviation": deviation,
        "actual_delta": actual_delta,
        "predicted_delta": predicted_delta,
        "elapsed_ms": (time.perf_counter() - t0) * 1000,
    }
```

```python
"""校准缓存 — diagnosis_hash → J 矩阵的持久化存储"""
import hashlib, json, numpy as np
from pathlib import Path

CACHE_DIR = Path("outputs/calibration_cache")

def diagnosis_hash(diagnosis) -> str:
    """诊断 → 确定性 hash (用于缓存键)"""
    d = diagnosis.to_dict()
    raw = json.dumps(d, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256(raw.encode()).hexdigest()[:16]

def load_cached_j(diagnosis) -> np.ndarray | None:
    """读取缓存的 J 矩阵。无缓存返回 None。"""
    key = diagnosis_hash(diagnosis)
    path = CACHE_DIR / f"{key}.npz"
    if path.exists():
        data = np.load(path)
        return data["J"]
    return None

def save_cached_j(diagnosis, J: np.ndarray) -> None:
    """保存 J 矩阵到缓存。"""
    CACHE_DIR.mkdir(parents=True, exist_ok=True)
    key = diagnosis_hash(diagnosis)
    np.savez(CACHE_DIR / f"{key}.npz", J=J)
```

## 3. 性能对比

| | SPEC-004 原版 | SPEC-004-REV |
|---|---|---|
| 默认路径 | 5 探针 × 4s = **20s** | 0 探针 = **0s** |
| 验证路径 | 同上 | 1 探针 × (1s DSP + 0.5s 轻量诊断) = **~1.5s** |
| 校准路径 | 5 探针 × 4s = 20s (每次) | 5 探针 × 1.5s = **7.5s** (仅异常歌, 结果缓存) |
| WAV I/O | 每探针写读删 | 无 (内存传递) |
| 诊断方式 | diagnose_quick (2-3s) | diagnose_lightweight (~0.5s) |
| 拟合方法 | 最小二乘 (恰好定) | 岭回归 (收缩估计) |
| 缓存 | 无 | diagnosis_hash → J 矩阵 |
