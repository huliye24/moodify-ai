# Moodify Desktop Phase 2.2 — A/B 审听与证据工作台优化

**Date:** 2026-10-04  
**Status:** IMPLEMENTATION BRIEF  
**Owner / final acceptance:** Codex（主控）  
**Implementation delegate:** DeepSeek / Claude Code  
**CANON_CHANGE:** NO — 不改变生产流程、判断权或声音契约，只优化已有候选与证据的呈现  
**MIP_REQUIRED:** NO  

## 0. 用户反馈与问题定义

真实歌曲已成功生成 A、B 两个候选，但当前 REVIEW 页面把它们挤在同一个波形和一张宽表里：

- 用户看不清当前正在听原版、A 还是 B；
- 页面视觉上像“只有一条音轨”，两个真实候选的存在感不足；
- A 与原版的频谱、图表和变化没有形成一个完整审阅单元；
- B 与原版的频谱、图表和变化也没有形成一个完整审阅单元；
- “保留 A / 保留 B”更像文字按钮，而不是听完证据后的选择；
- 51 项横向大表适合审计，不适合作为第一层判断界面。

这里的“A、B 两条音轨”是两个**完整候选版本**，不是重新引入多轨 stems，也不是声称已实现
逐轨修音。内部产物仍是现有：

```text
pair/A/mix.wav
pair/B/mix.wav
```

## 1. 唯一产品结果

将当前 REVIEW 区重构为清晰的 A/B 审听工作台：

```text
┌ 正在试听：A（保守） ─────────────── 原版 / A / B 快速切换 ┐
│  [A（保守）] [B（充分）]                                │
│                                                         │
│  A 波形与播放头                                          │
│  A vs 原版：频谱 · 关键指标 · 图表 · 实际处理链            │
│                                                         │
│  [选择 A]                        [保留原版]                │
└─────────────────────────────────────────────────────────┘
```

切到 B 标签页时，同一结构完整展示 B 与原版的比较。

用户在任何时刻都必须明确知道：

1. 当前标签页是谁；
2. 当前真正播放的是谁；
3. 当前播放时间在哪里；
4. A/B 分别相对原版改变了什么；
5. 当前选择状态是什么；
6. 机器只报告变化，不替人判断“更好”。

## 3. 信息架构

### 3.1 REVIEW 顶部：永久可见的试听身份

在播放器上方提供一个强可见状态：

```text
正在试听
[ 原版 ] [ A · 保守 ] [ B · 充分 ]
```

要求：

- 当前播放源必须用填充色、图标和文字三重表达，不能只靠颜色；
- 播放按钮旁持续显示 `正在试听：原版 / A（保守） / B（充分）`；
- 浏览 A 标签但正在播放原版时，必须同时显示：
  - `当前页面：A（保守）`
  - `正在试听：原版`
- 浏览 B 标签但正在播放 A 时同理，禁止把“当前标签”冒充“当前播放源”；
- 切换播放源后，标签、播放器状态和选择按钮立即一致更新。

建议固定颜色语义：

```text
原版 = 中性灰
A    = 蓝紫
B    = 橙色
```

颜色需满足可读性要求，同时保留文字标签，不能让色觉差异成为唯一线索。

### 3.2 两个候选标签页

主审阅区设置两个一级标签：

```text
[ A · 保守 ] [ B · 充分 ]
```

每个标签页只回答一个问题：

```text
这个候选相对原版发生了什么？
```

不要创建第三个“原版详情”标签。原版是 A、B 共同的比较基准，通过顶部试听源和每个候选页中的
对照列进入。这样用户不会在三个详情页之间迷路。

标签必须携带状态：

- `可听`：mix.wav 与证据齐备；
- `当前试听`：播放器正在播放该候选；
- `已选择`：decision 当前保留该候选；
- 缺产物时明确显示 `不可用`，不能留一个能点击但没有声音的标签。

### 3.3 每个候选标签页的固定结构

A、B 两页使用相同组件和相同尺度：

1. 候选身份与诚实说明；
2. 波形与统一播放器；
3. 候选频谱 vs 原版频谱；
4. 关键指标变化；
5. 图表对比；
6. 实际处理链与参数；
7. 完整复检表（折叠）；
8. 选择动作。

相同指标必须使用相同坐标范围、单位、小数精度和颜色规则，否则 A/B 无法公平比较。

## 4. 播放器与切换规则

### 4.1 一个 transport，三个真实音源

继续使用一个播放器控制面，但它可以加载：

```text
ORIGINAL
A
B
```

不得同时播放两个源。不得创建三个互不知情的 AudioContext 或三个不同播放头。

### 4.2 同位置切换

切换原版/A/B时：

- 保留同一个时间位置；
- 保留当前缩放范围；
- 若正在播放，优先实现无歧义的同位置切换；
- 若无法可靠无缝切换，允许短暂停顿，但必须从同一位置继续；
- 播放头、时间文本和波形高亮必须同步；
- 不得因为切换源把播放位置偷偷归零。

允许极短的加载态：`正在加载 B…`。加载失败必须显示真实原因，并保持上一个可播放源，不得把按钮状态
切成 B 后仍播放 A。

### 4.3 音量与增益

- 默认播放真实文件，不做 renderer 私有响度归一化；
- 本阶段不新增“响度匹配”DSP；
- 不在浏览器端偷偷改变 A/B 增益；
- 若未来加入 gain-match，必须是显式、可见、可关闭且有证据的独立任务。

## 5. A / B 各自的证据视图

### 5.1 身份卡

每页顶部显示：

```text
A（保守） / B（充分）
快速完成（仅立体声）
UNCALIBRATED_ENGINEERING_DEFAULT
机器已处理并测量；是否更好由你试听决定。
```

B 只能描述为“充分 / 变化更明显”，禁止写“增强版、最佳、更好”。

### 5.2 波形

当前标签页展示对应候选的真实 waveform，并明确标注：

```text
A 候选波形
B 候选波形
```

可提供“叠加原版轮廓”的辅助开关，但默认应保持清晰；若做叠加：

- 原版必须使用中性灰；
- 图例永久可见；
- 两者使用同一时间轴和同一幅度尺度；
- 不得通过各自自动缩放制造视觉差异或掩盖差异。

### 5.3 频谱对比

每个候选页必须有自己的频谱区域：

```text
A 标签：原版频谱 vs A 频谱
B 标签：原版频谱 vs B 频谱
```

优先复用 Core 完整 analyze 已生成的真实频谱图/数据。允许两种呈现：

- 同坐标叠加，带清晰图例；或
- 左右并排，但坐标范围完全一致。

要求：

- 图表标题写明来源；
- log / linear 频谱可切换；
- 图像或数据路径必须来自对应 recheck report；
- 缺图时显示“该复检报告未提供频谱”，不得用原版图冒充候选图；
- Desktop 不自行发明频谱数值，不建立第二套分析权威。

### 5.4 关键指标摘要

不要把 51 项表格直接作为首屏。先展示 6–10 个适合审听定位的真实指标卡，例如只有在 report 中存在时：

```text
Integrated LUFS
True / sample peak
Loudness range / dynamic range
Bass / core-mid / brilliance / air 能量
Stereo width / correlation
Clipping / finite 等硬门禁
```

每张卡固定显示：

```text
指标名
原版值 → 候选值
Δ 实际变化
单位
```

纪律：

- 指标选择可以固定，但值必须来自 recheck；
- 缺失就写 `不可对齐`，不得补算；
- 不用红/绿暗示变差/变好；
- 正负只表达数学方向，不表达审美方向；
- 不生成综合评分、质量分或推荐分。

### 5.5 图表区域

把已有检测图表按候选组织为：

```text
原版 | 当前候选
```

至少支持当前 Core 报告真实提供的图。A 页绝不混入 B 的 report，B 页绝不混入 A 的 report。

如果图表只存在于原版而候选复检没有生成，必须明确说缺失，不能复制原版图占位。

### 5.6 实际处理链

从现有 `plan.json` / `evidence.json` 展示只读处理摘要：

```text
EQ → Compressor → Stereo（若启用）→ Limiter
```

展开后显示实际参数和 Mix Graph digest。此区用于解释“A/B 为什么不同”，不得提供会绕开 Core 的
renderer 参数编辑功能。

### 5.7 完整复检表

保留现有 51 项对齐表作为审计层，但按当前标签过滤：

```text
A 页：指标 | 原版 | A | ΔA | 单位
B 页：指标 | 原版 | B | ΔB | 单位
```

完整表默认折叠，标题显示：

```text
查看全部 51 项复检指标
```

提供“仅看有变化 / 全部 / 不可对齐”筛选。不可对齐项必须保留真实原因。

## 6. 选择与导出体验

每个标签页底部提供与当前对象一致的主要动作：

```text
A 页：[选择 A（保守）]
B 页：[选择 B（充分）]
共同出口：[保留原版]
```

要求：

- 用“选择”而不是“保留 A/B”，减少与“保留原版”的语义冲突；
- 选择按钮必须继续调用现有 `tuning:decision`，不得建立 UI 私有选择状态；
- decision 成功后显示 `当前选择：A / B / 原版`；
- 切换标签不会改变选择；
- 选择 A 后仍允许试听 B，也允许通过新 request_id 改选；
- 未选择时导出保持锁定；
- 导出区域明确显示将要导出的对象和文件身份。

## 7. 数据与 IPC 边界

优先复用：

- `tuning:audio`：ORIGINAL / A / B 音频；
- `tuning:recheck`：三方对齐；
- pair 的 `plan.json` / `evidence.json`；
- recheck 中引用的 original / A / B report；
- report 已生成的频谱和图表文件。

如现有 IPC 无法安全读取候选 report 图表，可新增**只读** IPC，但必须：

- 路径经过 case root 与 pair_id 守卫；
- 只允许读取当前 case 内、recheck 明确引用的报告与图片；
- 不接受 renderer 任意绝对路径；
- 不重新运行分析；
- 不计算新的测量；
- 不修改任何 evidence。

不要把二进制大图或完整音频复制进新的状态文件。

## 8. 页面优化原则

- REVIEW 首屏优先回答“我正在听谁”和“它相对原版变了什么”；
- 细节逐层展开，不把审计表当主界面；
- A/B 页面结构严格对称，避免暗示某一档更重要；
- 原版始终是共同基准，不在页面滚动后消失；
- 关键试听控制与当前身份保持 sticky；
- 长曲波形不能把页面横向撑破；
- 适配当前桌面窗口宽度，避免必须横向滚动才能看到单位或选择按钮；
- 保留键盘可操作与清晰焦点状态。

## 9. 必须新增的测试

### 9.1 Renderer contract

- 存在 A、B 两个候选标签；
- 存在独立的“当前页面”和“正在试听”状态；
- A 页只绑定 A report/evidence，B 页只绑定 B；
- 原版/A/B 切换都调用真实 `tuning:audio`；
- 切换音源时位置不归零；
- 加载失败不会出现“显示 B、实际播放 A”；
- A/B 标签文字不含“更好、最佳、推荐”；
- 未校准状态持续可见；
- 完整表默认折叠且按当前候选过滤；
- “选择 A/B/保留原版”仍走同一 decision 门禁。

### 9.2 数据守恒

使用一份真实合成音频闭环产物验证：

```text
A 页展示的音频 hash = pair/A/mix.wav
B 页展示的音频 hash = pair/B/mix.wav
A 页 report path = recheck.paths.A
B 页 report path = recheck.paths.B
原版 path          = recheck.paths.original / case source
指标卡数量 + 完整表项目 = recheck 的 alignable / not_alignable 守恒
```

### 9.3 安全与失败

- 伪造 pair_id 不能读取其他 case 文件；
- recheck 引用越界路径时拒绝读取；
- 缺候选频谱时显示缺失，不回退成原版图；
- 缺 A 或 B 音频时相应标签不可播放、不可选择；
- 没有有效 recheck 时选择按钮保持锁定。

### 9.4 回归

必须通过：

```text
cd moodify-desktop && npm test
python scripts/check_repo_structure.py
python -m ruff check moodify-core-package/src moodify-core-package/tests
```

## 10. 人工验收脚本

使用真实歌曲生成完整 A/B 后：

1. 进入 REVIEW，第一眼能确认当前正在听谁；
2. 点击 A 标签，页面只展示 A 与原版；
3. 播放至歌曲中段，在原版/A/B之间切换，时间位置不归零；
4. A 页看到原版 vs A 的频谱、指标、图表和处理链；
5. B 页看到原版 vs B 的对应内容，尺度一致；
6. 展开完整表，A 页没有 B 列，B 页没有 A 列；
7. 选择 A，切到 B 试听，当前选择仍显示 A；
8. 改选 B，decision 追加成功；
9. 改选原版，仍经过同一道门；
10. 导出区准确显示最终选择。

人工验收需要截图记录 A 页、B 页以及三种试听源状态，但不得提交私有音频。

## 11. Definition of Done

只有同时满足以下条件才完成：

```text
A/B 两个候选被呈现为两个清晰标签页
当前页面与当前播放源永远可辨认
原版/A/B 可在同一时间位置切换
A 页有原版 vs A 的真实频谱、图表、指标与处理链
B 页有原版 vs B 的对应证据
完整复检表仍可审计但不再压住首屏
所有数值来自现有 report/recheck/evidence
没有综合听感评分，没有机器替人选
选择和导出继续使用现有权威门禁
没有第二套分析、DSP、状态机或 decision authority
全部测试与人工验收通过
```

## 12. 明确不做

- 不修改 A/B 的声音或参数；
- 不重新生成候选；
- 不实现逐轨音准/节奏修正；
- 不实现多轨复合；
- 不新增自动推荐 A/B；
- 不做 renderer 私有响度归一化；
- 不把频谱差异解释成好坏；
- 不建立新的 report、recheck 或 selection 权威；
- 不重写整个 Desktop；
- 不扩展到移动端、云端、账户或 Network。
