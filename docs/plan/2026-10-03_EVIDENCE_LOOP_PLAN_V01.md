## 0. 一句话方案

**给 Moodify 装上"研究侧账本"：壳内的 A/B 试听变成可落账的人类判断通道，处理结果自动生成证据库同构记录，成熟度由情绪波工程学的 M 阶梯裁定——把 Asset Loop 从文档画的东西变成跑起来的东西。**

```text
                    产品面（不动 canon）                    研究面（文川院）
  Studio/CLI 处理 ──► 版本树(evidence.json 增补五项分项) ──► 证据库 JSONL
  Studio A/B 条 ────► 研究模式判断记录(5级+元数据) ────────► observations/盲听记录
  门禁 M3/M4/M5 ◄──── 转化队列(只认证据库来源) ◄────────────  成熟度升级
  Studio 版本状态标 ◄── M 等级映射(显示层) ─────────────────
```

产品面不变量全部保留：版本不排名、delta 只描述不评级、渲染显式触发、AI 单门。研究侧账本是**新增通道**，不是给版本树加排行榜——两本账，物理隔离。

## 1. 任务分解

### T1 感知通道（最高优先，地基）

**目标**：跑通第一轮响度匹配匿名盲听，产生 0 → 1 的 M3 级证据；OBS-20260730-001 的 `human_blind_review=pending` 结案。

**现状缺口**：壳有常驻 A/B 试听条（v0.2 §4.5），但试听是"出耳"动作，没有"落账"动作。研究侧证据 0 条感知数据。

**方案**：

1. 研究侧数据结构（`~/.moodify/research/`，与 case 目录隔离）：
   - `judgments.jsonl`：每条 = 判断ID + 作品ID(匿名) + 版本对(a,b) + 5级判断（明显更好/略好/听不出/略差/明显差，以 a 为参照）+ 是否响度匹配 + 评判者角色（creator/listener/pro）+ 时间 + case 指针。
   - 字段与文川院 `observations.csv` 的感知列同构，便于定期合并。
2. Studio 接线（纯壳）：
   - A/B 条加一个"研究模式"开关（默认关）。开启后每次切换播放不记，显式点"记录判断"才落账——**判断必须是被动的，不自动抓行为**。
   - 开关态与评判者角色存 `~/.moodify/research/prefs.json`。
   - 界面无出口：记录完只显示"已入账 #N"，无统计、无排名。
3. 第一轮盲听（人工执行，协议引 EXP-001 PROTOCOL_v0.1）：
   - OBS-001 三个版本（原始 / Moodify候选 / 发布安全母带）匿名化 + 响度匹配后，壳内跑一轮；
   - 协议本身已有预注册，执行人与 AI 角色分开（AI 只负责组装刺激与记录，不评价）。
4. M3 升级门槛（引转化队列）：≥3 作品、各 ≥3 轮匹配盲听、方向一致性可报告（报告不评级）。**第一轮目标是 1/1 作品有记录，不是达标**——先打通管道。

**验收**：`judgments.jsonl` 存在且首条可追到 case；OBS-001 状态改为已盲听；研究模式开关可关、可查、无界面出口。

**自治级别**：实现全部 AI 自主（壳 + 数据结构 + 协议执行物）；盲听本身人工。

### T2 证据回流（与 T1 并行）

**目标**：CLI/Studio 每次渲染结束自动产一条证据库同构记录，转化队列门禁有真实来源。

**方案**：

1. 渲染完成钩子（Core 侧，改动最小化）：
   - 版本目录的 `evidence.json` 增补五项分项（对齐 PRINCIPLE-001 净增益分解）：`loudness_delta / identity_delta / artifact_risk / duration_check / complexity_cost`——**全部是测量值，不合并成分数**（宪章："第一阶段不强行合并"）。
   - 该字段是 additive 的，不碰 Mix Graph / 硬门 / 身份门既有语义。
2. 落库（壳/CLI 侧）：
   - 自动追加 `~/.moodify/research/evidence.jsonl`：证据ID + 研究ID(作品) + 证据等级=M1 + 数据入口 + technical_gate 状态 + 感知状态=pending + 回滚指针。
   - **不跨仓库直写文川院目录**：文川院是权威证据库，同步是显式人工动作（复制/导入，保留人类审批门）。自动写 `~/.moodify/research/`，人工晋升到文川院。
3. 门禁映射（文档 + 显示层）：
   - M 等级 → Studio 版本状态标签：M3 可试听 / M4 影子运行 / M5 可申请主线（映射表进 `docs/`，显示只读，不改变版本树的"不排名"——这是成熟度标记，不是排行榜）。

**验收**：跑一次完整渲染 → `evidence.jsonl` 新增一条、`evidence.json` 含五项分项、既有五道门全绿；M 映射表可查。

**自治级别**：实现 AI 自主；evidence.json 字段扩展属 additive，但过 Core 五道门。

## 4. 明确不做

- 版本树加排行榜 / 把研究统计显示进产品界面；
- 算法自动评级（只记录人类判断，A/B Judge 仍走显式召唤既有通道）;
- 自动跨仓库写文川院（同步永远是人工动作）；
- 把 MATH-001 未拟合参数写成任何数值承诺（宪章红线，同样适用于书）；
- 在 T1 出数据前写 ch27–29 成稿。

## 5. 风险

| 风险 | 处置 |
|---|---|
| 研究模式开关变成第二套产品心智 | 开关默认关；记录界面零出口；面板不显示任何汇总 |
| 证据 JSONL 与 case 目录双源不一致 | case 是事实源，JSONL 只存指针+镜像字段，冲突以 case 为准 |
| 盲听执行者被污染（先看过版本名） | 匿名化在组装阶段完成，评判者只见 a/b 代号；顺序随机 |
| T2 钩子拖慢渲染 | 落账在渲染完成后异步执行，失败只告警不阻塞版本入树 |
