## 0. 为什么需要 V02

V01 把 Phase 1 定义为「S3 布局 + Studio 发布链路改造」。实际执行后实测得到三个与 V01 假设不符的事实：

1. **发布链路改造只完成了「不需要云权限」的一半。** 并发、异步、幂等三项做完了；S3 数据面一行未写。
2. **「去掉重启」不可能由 Studio 单独完成。** 静态探针已反证：manifest 仍在 `dist/client/` 下，vinext 启动时索引静态资产，新增/变更文件不重启即 404。这不是没做，是**当前架构下做不到**。
3. **V01 §7 承诺的回滚开关 `PUBLISH_BACKEND` 从未写入代码。** 全仓搜索为空。

V02 的任务：把 V01 的承诺与实际逐条对齐，只保留仍然成立的部分，把剩余工作重排成**可执行、可验收、可回滚**的单元，并明确哪些必须等待人类授权。

## 2. 仍然成立的设计（V01 §3 不推翻）

V01 的三条发现（香港是带宽瓶颈而非性能瓶颈 / 三域名全在 Cloudflare 后、香港靠 Tunnel 出站 / 宁夏两台当前无任务）**未被推翻**，故三面分离的架构判断继续有效。

```
        Moodify Studio（本机 Windows）
             │
             ① ffmpeg 本地转码  WAV 40MB ──▶ AAC ~4MB   （省 82.7%）
             │
             ② HTTPS 直传 S3（国内直连，已验证 ~70MB/s）
             ▼
    ┌─────────────────────────────┐
    │  宁夏 S3  moodify-dataset   │  ← 数据面：音频 / 封面 / 歌词
    │  raw/non-ai/works/<id>/     │     国内直连，绕开香港 18 Mbps
    └─────────────────────────────┘
             ▲                    ▲
             │ ③ 注册元数据        │ ⑤ 直连下载（不经香港、不经 CF）
             │   （几 KB JSON）    │
    ┌────────┴────────┐      ┌────┴─────┐
    │ 香港 103.144... │      │ 手机 App │
    │ 控制面：        │      └──────────┘
    │  manifest.json  │
    │  预签名 URL     │
    │  CF Tunnel 暴露 │
    └────────────────┘

    宁夏 GPU（异步，仅 R5 需要）
      S3 取 job ──▶ demucs / Core 分析 ──▶ S3 写回结果
      ▲ 两端不直接通信，一个端口都不用开（绕开硬约束 2）
```

| 层                       | 位置     | 流量   | 理由                       |
| ----------------------- | ------ | ---- | ------------------------ |
| 控制面（manifest / 鉴权 / 签名） | 香港     | KB 级 | 无需备案，200ms 延迟可接受         |
| 数据面（音频 / 封面 / 歌词）       | 宁夏 S3  | MB 级 | 国内直连，绕开 18 Mbps 与 CF 不稳定 |
| 计算面（分析 / 分离）            | 宁夏 GPU | 内部   | 走 S3 异步队列，两端不需要互通        |

## 3. 剩余工作分解

按「是否依赖云侧授权」排序。R1、R2 **完全不需要任何云权限**，可以立刻做；R3 必须并入 R4；R5 当前无任务可跑。

### R1 — 补回滚开关 `PUBLISH_BACKEND`（无云依赖 · 应最先做）

**目标**：让 R2 的改造具备退路。V01 §7 已承诺但未实现。

- 取值 `scp`（默认，行为与今日完全一致）| `s3`（走新路径）
- 未知值安全回退到 `scp` 并显式告警，不静默当作 `s3`

**判据**：设 `PUBLISH_BACKEND=scp` 时，发布路径与今日逐字节一致；设非法值时回退 `scp` 且界面/日志可见。

**为什么排第一**：先有退路，再改路径。顺序反了就会得到一个"单向"的改造。

---

### R2 — 本地转码 + S3 直传接入发布链路（无云依赖）

**前置能力均已核验**：ffmpeg 9.0.2 在 `moodify-desktop/build/runtime/ffmpeg/ffmpeg.exe`；本机 → `s3://moodify-dataset/raw/non-ai/` 直传已打通（13GB / 3 分钟）；`s3Layout()` 键生成已就绪。

**做法**：

1. 发布前把源 WAV 用 ffmpeg 转 AAC 256k（Phase 0 实测省 **82.7%**，时长漂移 0.000s）
2. 直传 `s3://moodify-dataset/raw/non-ai/works/<work_id>/{audio.m4a,cover.jpg,lyrics.lrc}`
3. 复用已完成的内容指纹幂等（`uploadNeeded`），**已在 S3 的资产不重传**

**⚠️ R2 的诚实边界（重要）**：S3 上传完成后，**App 端还不知道去 S3 读** —— 清单里的 `audio_asset_key` 仍指向香港 `/audio/`。因此 R2 只能做到**双写**（S3 存一份作为冷备与未来切换准备），真正让 App 从 S3 读取必须等 R4（控制面 + 读取授权）。R2 不应被表述为"发布了新链路"，只能表述为"新链路已就位但未接管"。

**判据**：

- 上传后 S3 对象 sha256 与本地一致
- 重复发布同一作品触发零次重复上传
- 转码产物体积 ≤ 源 20%，时长漂移 < 0.05s
- `PUBLISH_BACKEND=scp` 时全部新代码不执行

**回滚**：`PUBLISH_BACKEND=scp` 即回旧路径；S3 侧对象无害（仅多占存储，且无 DeleteObject 权限，不尝试清理）。

---

### R3 — 去掉重启（**必须并入 R4**，不可单独完成）

**反证依据**：`src/main.js:338-340` 记录的实测 —— 在 `dist/client` 下新建文件后 HTTP GET 返回 404，说明 vinext 启动时索引静态资产。

**做法**：把 manifest 移出 `dist/client/`，改由 nginx 以 `no-store` **直接服务静态文件**。写完即生效，永久消灭重启。

**接口位已预留**：`src/main.js:341-347` 已有 `opts.refresh === 'none'` 分支与注释（"清单由 nginx 直服"），只等服务端落地即可切换。

**判据**：`refresh: 'none'` 下发布一首新歌，线上立即可见且 `moodify-music.service` 的 uptime 未归零。

---

### R4 — 控制面（**需人类显式授权**）

**授权冲突提示**：V01 §6.2 已指出，这与项目铁律「禁止部署到云端生产」直接冲突。香港承载 25 个 active service（`rongjingmusic.com` / `crestwavecoin.com` 等），修改前须备份 + 显式放行。

**内容**：

1. nginx 改动：manifest 移出 `dist/client/`，`no-store` 直服（承接 R3）
2. 元数据 API：接受 Studio POST 注册/更新作品条目
3. 读取授权三选一（V01 §「Phase 2 读取授权」原表仍有效）

| 选项                    | 做法                                                                      | 优点               | 缺点                                        | 需要的授权     |
| --------------------- | ----------------------------------------------------------------------- | ---------------- | ----------------------------------------- | --------- |
| **A（推荐）** 公开读 + 不可猜路径 | 关 Block Public Access + bucket policy `Allow GetObject`，路径含随机 `work_id` | 零运维、无凭据分发、国内直连最快 | 链接泄露即可下载；有盗刷流量风险（可加 `aws:Referer` 条件缓解）   | 管理员改桶策略   |
| **B** 预签名 URL         | 香港持 IAM 长期 key，只做 HMAC 签名（纯本地计算，不需访问 AWS 网络）                            | 可控、可审计、可吊销       | 需创建 IAM 用户并保管 key；URL 有有效期                | 创建 IAM 用户 |
| **C** 宁夏 CPU 跑签名服务    | m6i 常开提供签名                                                              | 数据与控制同区          | 需常开机 + 开端口，**中国区 80/443 有 ICP 备案要求**，风险最高 | 开机 + 备案评估 |

**回滚**：nginx 配置先 `cp` 备份，改完 `nginx -t` 校验再 `reload`；失败即还原备份。

### R5 — 计算面 GPU 异步队列（**当前不应开工**）

**前置不满足**：Core 侧逐轨分离仍未实现（`protocol/mips/MIP-0002-stem-tuning-loop.md` 仍为 DRAFT），**没有可远程执行的任务**。开机即烧钱。

**机制（届时照此实现，绕开硬约束 2，两端不直接通信）**：

```
Studio 写 s3://moodify-experiments/jobs/pending/<job_id>.json
   ↓
GPU 节点轮询 pending/ → 取任务 → demucs / Core 分析
   ↓
写 s3://moodify-experiments/jobs/done/<job_id>.json
   ↓
Studio 轮询结果
```

**纪律**：任务跑完立即停机。GPU 不是常驻服务，是批处理资源。

**另一条阻塞**：`MoodifyExperimentWorkerRole` 当前对 S3 **零权限**（两桶全部 AccessDenied），根因是策略文件名带 `.proposed` 且**从未 attach**。修复只能人手在控制台做，策略已备于 `E:/亚马逊云/宁夏CPU节点/iam-worker-policy.json`。

## 4. 硬纪律（不变量，不得违反）

1. **未经人类显式放行，不得修改云端生产**（AGENTS.md 铁律；R4 冲突项须单独放行）。
2. **音频上传不得经过香港**（出口仅 ~18 Mbps，且是全部线上服务的单点）。
3. `DeleteObject` 未授权 → **禁止** `sync --delete` 及任何删除远端对象的动作。
4. `aws s3 ls`（不带前缀）**必然 403，是设计如此**，不得用作权限判据。
5. 宁夏机器**未绑弹性 IP**，`stop → start` 会换公网 IP；连不上先查控制台公网 IPv4，不要先怀疑安全组。
6. 不得新增第二套 Core / 状态机 / 判断权威（`JUDGE_CORE_PRINCIPLE.md`）。
7. **Phase 0–R4 全程不需要宁夏开机**；只有 R5 需要。
8. 任何阶段都必须**先有回滚手段再动路径**（R1 必须早于 R2）。
