# Genesis Airdrop

**Package:** MOOD-GENESIS-005  
**Name:** Merkle Airdrop  
**Purpose:** On-chain MOOD distribution via Merkle proofs

This document describes the smart contract and frontend for Genesis MOOD claims.

---

## Overview

The Genesis Airdrop allows approved Genesis participants to claim their MOOD allocation using Merkle proofs generated by Package 004.

**Flow:**

```
Package 004 Snapshot
    ↓
Human approves Merkle root
    ↓
Deploy MoodGenesisDistributor
    ↓
Fund with MOOD tokens
    ↓
Participant connects wallet at /airdrop
    ↓
Frontend loads proof
    ↓
Participant submits claim
    ↓
Contract verifies proof
    ↓
MOOD transferred to participant
```

## Contract Architecture

### MoodGenesisDistributor

**Location:** `contracts/protocol/MoodGenesisDistributor.sol`

**Design Principles:**
- Immutable Merkle root
- Immutable token address
- Optional immutable deadline
- Optional immutable recovery owner
- No proxy/upgradeability
- No mint capability
- SafeERC20 for transfers

**State Variables:**

```solidity
IERC20 public immutable token;           // MOOD token
bytes32 public immutable merkleRoot;   // Approved root
uint256 public immutable claimDeadline;  // Optional deadline
address public immutable owner;          // Optional recovery

mapping(uint256 => bool) public claimedParticipant;
uint256 public totalClaimed;
```

**Constructor:**

```solidity
constructor(
    address _token,        // MOOD token address
    bytes32 _merkleRoot,   // Package 004 approved root
    uint256 _claimDeadline, // 0 for no deadline
    address _owner          // address(0) for no recovery
)
```

**Claim Function:**

```solidity
function claim(
    uint256 participantNumber,
    uint256 amount,
    bytes32[] calldata proof
) external
```

**Verification Order:**
1. Check deadline (if set)
2. Check not already claimed
3. Validate amount > 0
4. Construct leaf: `keccak256(abi.encode(participantNumber, msg.sender, amount))`
5. Verify Merkle proof
6. Mark claimed (before transfer)
7. Transfer MOOD
8. Emit Claimed event

**Recovery (if enabled):**

```solidity
function recoverUnclaimed(address recipient) external
```

Requirements:
- Only callable by owner
- Only after deadline
- Only if owner was set in constructor

## Merkle Compatibility

### Leaf Encoding (Package 004 Format)

```solidity
// Types
["uint256", "address", "uint256"]

// Values
[participantNumber, account, amountAtomic]

// Leaf hash
keccak256(abi.encode(participantNumber, account, amount))
```

### Tree Construction

OpenZeppelin StandardMerkleTree convention:
- Sort sibling hashes before concatenation
- Build tree bottom-up
- Root is final hash

### Proof Verification

```solidity
function _verifyProof(bytes32 leaf, bytes32[] calldata proof)
    internal
    view
    returns (bool)
{
    bytes32 computedHash = leaf;

    for (uint256 i = 0; i < proof.length; i++) {
        bytes32 proofElement = proof[i];

        // Sort for deterministic ordering
        if (computedHash <= proofElement) {
            computedHash = keccak256(
                abi.encodePacked(computedHash, proofElement)
            );
        } else {
            computedHash = keccak256(
                abi.encodePacked(proofElement, computedHash)
            );
        }
    }

    return computedHash == merkleRoot;
}
```

## Security Invariants

1. **Only approved leaves can claim**
   - Proof must verify against stored root

2. **Each allocation claimed once**
   - `claimedParticipant` mapping prevents double claims

3. **Claim amount cannot be changed**
   - Amount is part of leaf hash

4. **Claim wallet cannot be redirected**
   - `msg.sender` must match leaf account

5. **Root cannot be changed**
   - Immutable after deployment

6. **Contract cannot mint MOOD**
   - Only transfers from funded balance

7. **Claimant never approves MOOD**
   - Distributor sends MOOD directly

## Frontend

### /airdrop Page

**Location:** `app/airdrop/page.tsx`

**States:**

| State | Description |
|-------|-------------|
| `disconnected` | Show connect wallet prompt |
| `wrongNetwork` | Require BNB Smart Chain |
| `checking` | Verify eligibility |
| `notEligible` | Not in Merkle tree |
| `eligible` | Show claim details |
| `confirming` | Wallet confirmation pending |
| `pending` | Transaction submitted |
| `claimed` | Success with receipt |
| `error` | Handle errors |

**Safety Features:**

- Never requests MOOD approval
- Shows transaction preview before signing
- Confirms claim from chain receipt
- Links to BscScan for verification

### API Endpoint

**GET /api/airdrop/eligibility?address=0x...**

**Returns:**

```json
{
  "eligible": true,
  "participantNumber": 1,
  "amountMood": "1000",
  "amountAtomic": "1000000000000000000000",
  "proof": ["0x..."],
  "claimStatus": "unclaimed"
}
```

**Does NOT return:**
- Internal admin notes
- Raw signatures
- Nonces
- Private user profile fields

## Deployment

### Local Testing

```bash
# Start local node
anvil

# Deploy
forge script contracts/script/DeployLocal.s.sol --rpc-url local --broadcast
```

### Production (BNB Smart Chain)

**Prerequisites:**
1. Approved Package 004 snapshot
2. Approved Merkle root
3. MOOD tokens for funding

**Environment Variables:**

```bash
export PRODUCTION_PRIVATE_KEY=<your_private_key>
export MERKLE_ROOT=<approved_root>
export CLAIM_DEADLINE=<unix_timestamp_or_0>
export RECOVERY_OWNER=<owner_address_or_0>
export SNAPSHOT_ID=<package_004_snapshot_id>
export SNAPSHOT_SHA256=<snapshot_hash>
export PARTICIPANT_COUNT=<count>
export TOTAL_MOOD=<total>
export GIT_COMMIT=<commit_hash>
```

**Dry Run:**

```bash
forge script contracts/script/DeployProduction.s.sol --rpc-url bsc
```

**Deploy (Human Approval Required):**

```bash
forge script contracts/script/DeployProduction.s.sol --rpc-url bsc --broadcast
```

**Verify on BscScan:**

```bash
forge verify-contract \
  --chain-id 56 \
  --watch \
  <DISTRIBUTOR_ADDRESS> \
  contracts/protocol/MoodGenesisDistributor.sol:MoodGenesisDistributor
```

## Error Codes

| Code | Description |
|------|-------------|
| `AlreadyClaimed` | Participant already claimed |
| `InvalidProof` | Merkle proof verification failed |
| `ZeroAddress` | Token address is zero |
| `ZeroRoot` | Merkle root is zero |
| `ZeroAmount` | Claim amount is zero |
| `DeadlinePassed` | Claim after deadline |
| `DeadlineNotPassed` | Recovery before deadline |
| `UnauthorizedRecovery` | Not authorized for recovery |
| `InsufficientBalance` | Not enough MOOD in distributor |
